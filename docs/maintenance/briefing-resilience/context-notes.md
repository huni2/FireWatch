# 구현 근거

- 사용자는 무료 운영과 현재 서버 키 사용을 유지하며 보조모델·결과재사용·AI없는기본브리핑·예약 보완 구현을 승인했다.
- 공식 요금표에서 gemini-3.5-flash-lite 입력/출력 무료 제공을 확인했다. 실제 서버 키 사용 가능 여부는 배포 후 남은 정상 호출 예산 안에서 검증한다.
- 기존 DB category 실패 한도는 HTTP 요청 수와 달라, 보조 호출을 같은 작업 안에 넣을 때 예산을 별도로 영속화한다. 배포로 기존 당일 실패를 초기화하지 않는다.
- 루트 메모와 위키의 기존 작업 내용은 보존하고 이번 파일·이번 로그만 커밋한다.
- gemini_daily_usage는 요청 예산과 중지 상태만 저장하며 키/본문은 저장하지 않는다. PG RLS와 동시 UPDATE 예약으로 중복·재시작 한도를 검증한다. 당일 이전 collection_circuits 실패 횟수도 처음 예약에 반영한다.
- 추천은 저장된 브리핑·포함 기사만 검증한다. 빈 추천도 READY로 보관해 기존 API 계약을 유지한다. ai_analyzed_at에 실제 생성 시각을 저장하고 옛 자료는 미확인(null)으로 둔다. 과거 보고서는 수정하지 않는다.
- 서비스 패키지 밖의 주기 실행기가 DB 상태를 먼저 확인해 완료·대기·중지 작업의 빈 감사로그를 만들지 않는다. 최초10초/이후5분 주기는 서버가 깨어 있을 때만 동작한다.
- 전체 build 성공:263개 중262통과/1skip/실패0. 로컬 PC의 JVM 네이티브 메모리 부족은 유휴 Gradle 데몬 정리 및 JAVA_TOOL_OPTIONS=-XX:ActiveProcessorCount=2 -Xss512k, --no-daemon --max-workers=1, Gradle heap256MiB로 재검증했다. 실제 동시성 테스트는 유지했다.
- 무료 모델 전환 로컬HTTP, 일별3회/재시작/이전실패차감/동시예약,401·403·429중지, 자료없는AI호출차단, 정상·과거원문보존, 추천0건·동시보관·옛실패정리, 복구 빈 실제 Spring구성까지 확인했다. PG 전용 CI에도 신규 예산/보고서 통합 검증을 추가했다. README 링크32개 검사PASS. 아직 운영 배포/실제 보조모델 응답은 확인 전이다.

# 운영 API 전용 인증 전환

수집 실행·운영 진단·장애 푸시 등록·레거시 이전은 이제 감사로그와 같은 `OperatorAccess`를 사용한다. 익명 요청은 401, 로그인한 일반 사용자는 403, 공개 `SETTINGS_API_KEY`는 401이다. Google에서 검증된 운영자 이메일과 현재 기기에 연결된 서버 세션만 계정 인증으로 허용한다.

## 배포 순서

1. Render에 **OPERATOR_API_KEY**를 등록한다. 기존 공개 설정 키나 OAuth ID와 다른 무작위 비밀값을 사용한다. 값은 채팅·저장소·VITE_*·EXPO_PUBLIC_*에 넣지 않는다.
2. GitHub 저장소 Settings → Secrets and variables → Actions에 같은 **OPERATOR_API_KEY**를 등록한다. RENDER_BACKEND_URL은 유지한다.
3. 코드와 예약 수집 워크플로를 함께 배포한다. 이 준비 전에는 main의 기존 스케줄러 인증을 전환하지 않는다.
4. 새 서버 health와 GitHub 예약 워크플로 성공, 공개 키·익명 진단 거절을 확인한다. 사용자 기록을 지우거나 재수집해 확인하지 않는다.
5. 운영자 로그인 → 설정 → 브라우저 알림 등록 → 운영자 푸시 등록 → 수신 확인용 알림 보내기를 수행한다. 제공처의 발송 수락은 실수신 증거가 아니며 기기에서 직접 확인해야 한다.

예약 수집은 서버 전용 키를 사용하고 웹·앱 운영자는 로그인 세션을 사용한다. 추가 관리 키는 웹 감사로그의 메모리 인증 경로에서만 임시 입력할 수 있다. 기존 데이터 이전은 새 브라우저에서 직접 선택해야 하며 자동으로 실행하지 않는다.

## 출시 전·후 기록 이전

2026-10-10 사용자는 출시 전 기존 기록 이전이 불필요하다고 결정했다. BE-17의 현재 운영 확인은 이 결정으로 종료한다. 기존 기록과 선택형 이전 구현은 유지한다.

출시 후 이용자의 계정·기기 변경에서는 기존 관심 기업·포트폴리오를 보존해야 한다. 이미 같은 Google 계정에 연결한 공유 기록은 재로그인으로 조회하며, 별도 익명 기록의 합류·게임 이전과 구분한다. 레거시 운영자 복구 API를 일반 사용자에게 공개하거나 모든 기기 기록을 자동 합치지 않는다.

별도 기록을 옮길 때는 소유 확인과 사용자 선택을 먼저 확인한다. 대상 계정에 기록이 있으면 덮어쓰지 않고 충돌을 안내하며, 이전 전후 관심 기업·보유/이력·게임 등 실제 이전 범위를 비교한다. 앞으로 새 이전 기능을 구현할 때도 이 기준을 적용한다. 이번 종료를 출시 후 모든 종류의 자동 이전 검증 완료로 표현하지 않는다.

테스트 알림은 별도 제목이고 실제 수집 장애 기록을 만들지 않는다. 서버에서 1분 1회로 제한하며 자동 재시도하지 않는다. 실제 장애 outbox는 기존의 최대 3회·60분 간격을 유지한다. 테스트 실패는 FCM_PUSH FAILURE 감사로그로 남는다.

## 개발자 관점.

서버가 가격·체결·턴을 확정하고 클라이언트가 주문 총액을 즉시 계산하는 분담이 좋다. 요청 ID와 예상 턴·가격으로 재전송과 오래된 주문을 방어한다. 게임 시드를 저장해 재조회 시 같은 가상 가격과 사건을 재현한다. 실제 수집과 게임이 분리되어 게임이 제공처 오류에 영향을 받지 않는다. 실패 시 보유 자산을 0원으로 확정하지 않는 처리도 중요하다.

웹과 앱은 공통 계산·라벨·후보 검증·디자인 토큰을 공유한다. UI에는 로딩·실패·빈 결과·거래정지·근거 없음 상태가 구분되어 있다. 다음 턴 요청은 복기 연출과 병행하며 건너뛰어도 중복 요청이나 결과 조작을 하지 않는다. 다만 마지막 복기는 메모리에만 있고 새로고침 후에는 사라진다. 게임 자산 이력과 거래 원장은 서버에서 재조회한다.

익명 기기 ID는 접근 자격으로 사용한다. 무작위 ID와 공개 공용 ID 차단은 개선이지만 계정 세션의 만료·갱신·해지와 기기 해제까지 갖춘 인증을 대체하지 않는다. 공개 감사로그는 본문을 가렸지만 사용자 활동 자체를 공개 운영 화면에 둘 필요도 재검토해야 한다.

## 서버·데이터 관리 관점.

Render의 임시 디스크 대신 외부 DB를 사용하고 prod 설정이 없으면 시작을 실패시켜 H2로 조용히 전환하지 않는다. 뉴스·관측값·가격·수집 작업·장애 상태를 DB에 저장한다. 수집 실패는 카테고리별 한국 날짜 기준 상한과 대기 시간으로 제한하며, 작업 임대와 회로 상태로 여러 호출이 상한을 우회하지 않도록 한다. 장애는 감사로그와 화면, 지정 운영자 푸시 발송 대기열로 연결된다.

실제 운영자 수신자 등록과 휴대전화의 푸시 수신은 이번 검증에 포함되지 않았다. 제공처의 접수 성공과 기기 수신은 서로 다르며, 앱을 닫은 상태의 실제 수신까지 확인해야 한다. 뉴스는 저장된 제목·설명과 URL을 검색하며 원문 전체 및 수집 전 기사를 제공하지 않는다.

무료 인프라의 응답 시간은 아직 개선 과제다. 최종 API 실행에서 게임 시작 약 7.9초, 매수 약 3.6초, 다음 턴 약 2.0초였다. 전체 이력 조회는 첫 실행 24.3초, 쿼리 수정 후 실행 11.4초였다. 서로 다른 시점의 단일 표본이므로 성능 보장이나 동일 조건의 벤치마크로 볼 수 없다. SSE는 진행 상황을 보여줄 수 있지만 DB 왕복과 서버 기동 시간을 줄여주지 않는다. 요청별 DB 시간과 p95를 측정해 병목을 줄이는 작업이 우선이다.

## PM 관점과 앱의 정체성.

정체성은 개인 투자 계획과 보유 자산을 기준으로 시장 근거를 점검하는 투자 준비 앱이다. 가상 게임은 독립 학습·복기 경험이다. 실거래와 자동 보유 내역이 강한 은행 앱과 비교할 때, 여기서 기대할 아하 모멘트는 종목 후보를 더 받는 것보다 내가 가진 자산의 중복·집중과 후보의 이유·위험을 함께 이해하는 순간이다.

현재 포트폴리오 분석과 구성 초안은 규칙 기반 MVP이고, 브리핑 후보는 개인별 랭킹이 아니다. 상품별 실제 보수·추적오차·세금 등을 비교하는 ETF DB도 없다. 이 한계를 분명히 유지해야 한다. 가상 픽은 게임 시나리오 규칙으로 생성하며 실제 모델의 매수 판단처럼 소개하지 않는다.

가장 큰 제품 공백은 실제 추천 공급이다. 10월 7일 저장된 브리핑의 추천 이름은 3개지만 종목별 근거는 0개였다. 이전 자료에 근거를 꾸며 넣지 않아 현재 검증된 추천 후보는 0개다. 새 프롬프트·구조화 저장·검증 필터는 배포됐지만, 새 수집 결과가 실제로 이유·위험·관련 기사까지 갖추는지는 후속 운영 검증이 필요하다. 단순히 링크가 같은 브리핑에 존재하는 것만으로 내용의 사실성까지 검증되지는 않는다.

## UX·디자인 관점.

라이트 기본, 오렌지 포인트, 정보 카드와 게임 전용 공간은 방향이 일관된다. 픽의 이유·위험·가상 뉴스와 직접 만든 불꽃 정찰대가 이전의 밋밋한 숫자 화면을 개선했다. 픽에서 주문으로 바로 이동하고 총액 확인·체결 원장·가격 변화·턴 복기로 이어지는 흐름도 확인했다.

포트폴리오 첫 화면은 입력 항목과 빈 카드가 많아 아직 관리 화면의 느낌이 강하다. 자산 하나와 수량·평균 매입가를 등록한 뒤 첫 분석을 보여주고, 목표·계좌·추종 지수 등은 단계적으로 받는 방식이 다음 개선점이다. 분야 탐색은 7개 분야·14개 기업 시작 목록에 한정되며 전체 기업 목록이 아니다. 소형주·다양한 ETF를 기대하는 사용자에게 이 제한과 검색 진입을 더 잘 보여줄 필요가 있다.

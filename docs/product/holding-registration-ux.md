# 보유 자산 등록 UX — 웹·Android

2026-10-14. 사용자가 요청한 검색 목록 선택과 간단한 등록 흐름을 두 화면에 적용한다.

## 화면과 문구

- 새 등록은 `주식·ETF 검색 → 목록에서 선택 → 현재 보유한 총수량 → 보유 자산 등록`으로 진행한다.
- 검색 중에는 수량 입력을 숨긴다. 선택한 종목은 이름, 코드, 상장시장, 분류, 거래 통화를 카드에 표시한다. ETF의 확인된 추종 지수는 별도로 표시한다.
- `평균 구매 가격 입력 (선택)`을 펼치면 1주당 가격을 입력한다. 총 구매 금액이 아니라 증권 앱의 평균단가임을 설명한다.
- 새 등록에서 카탈로그로 확인한 종목은 기존 `상품 정보 더 확인하기`를 표시하지 않는다.
- 기존 기록 수정은 종목을 고정하고 수량·평균 구매 가격을 수정한다. 기존에 저장한 분류·지역·분야·추종 지수는 보존하며 `저장된 종목 정보 수정`에서 변경할 수 있다.
- 웹은 오른쪽 패널, 좁은 웹 화면과 Android는 화면 너비를 사용한다. 등록 버튼은 하단에 유지한다.

## 검색과 입력 보존

- `/api/catalog`의 종목 메타데이터로 등록 정보를 채운다. 클라이언트 내 작은 회사·ETF 목록에 없다는 이유로 ETF를 주식으로 분류하지 않는다.
- 검색은 300ms 입력 대기 후 실행하며 이전 검색의 늦은 응답이 새 결과를 덮어쓰지 않는다.
- 서버 정렬은 이름·코드 정확 일치, 이름 시작 일치, 부분 일치 순이다. 페이지별 결과를 이어서 표시하고 중복 코드를 제거한다.
- 카탈로그에 없는 종목은 기존 `/api/stocks/search`를 사용한다. 메타데이터가 없으면 `종목 정보 확인 필요`로 표시하고 등록 전에 정보를 보완·확인한다. 현 포트폴리오가 지원하는 한국·미국 코드 형식으로 제한한다.
- 등록된 종목은 `등록됨`으로 표시한다. 선택하면 기존 수량과 `기존 기록 수정`을 제공한다. 작성 중인 기록이 있을 때는 전환 전에 입력 취소를 확인한다.
- 다른 종목으로 변경하면 이전 수량·평균 구매 가격을 비우고 그 이유를 표시한다. 같은 종목을 다시 선택하거나 정보만 보완하면 입력값을 유지한다.
- 검색 실패는 결과 없음과 구별하고 검색어와 기존 결과를 유지한다. 저장 실패도 입력을 유지한다.
- 평균 구매 가격이 빠진 종목이 있으면 전체 투자원금·손익을 계산하지 않은 이유를 자산 요약에 표시한다. 수집 시세가 있는 자산의 비중 계산은 기존 규칙을 따른다.

## 검증 범위

- 공유 로직: 목록 밖 ETF 메타데이터, 종목 변경 초기화, 같은 종목 입력 보존, 중복·수량·선택 가격 검증, 페이지 전달, 외부 검색 보완, 통신 오류.
- 백엔드: 카탈로그 정렬·페이지, 기존 카탈로그 보존, 포트폴리오 API 통합 테스트.
- 웹: 타입·프로덕션 빌드·린트 및 1280px/360px 로컬 API fixture로 검색, 중복 수정, 입력 초기화, 저장 재시도, 정보 보완과 가로 넘침 검증.
- Android: 타입·린트 및 Android JS/Hermes 번들 생성. 2026-10-14 후속으로 1.0.12/빌드17 설치 APK를 로컬에서 생성하고 기존 서명·무결성·새 검색/등록 코드 포함을 검증했다. [빌드 기록](android-preview-20261009/android-112-build.json). 실제 기기 키보드·뒤로가기 검증은 별도다.

운영 배포, 외부 검색 제공처의 실제 응답, 새로운 APK 설치를 위 검증으로 대신하지 않는다.

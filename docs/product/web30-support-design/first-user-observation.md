# WEB-38 실제 첫 이용자·접근성 확인

2026-10-11 사용자 답변: 실제 첫 이용자 관찰은 아직 없음. 아래 결과는 아직 미확인이다. 자동 브라우저 검사 결과와 실제 사람의 관찰 결과를 구분한다. 대상은 https://firewatch-eqp.pages.dev 의 PC 웹과 모바일 브라우저다. Android 설치 앱 검증은 APK 보류가 해제된 후 APP-21에서 진행한다.

## 첫 이용자에게 줄 목표

FireWatch를 처음 쓰는 사람 1명 이상에게 다음 목표만 전달한다. 버튼 위치와 순서를 미리 알려주지 않는다. 관찰자가 도와줬으면 도움을 준 단계도 기록한다.

1. 관심 있는 회사를 찾고, 그 회사의 가격과 관련 뉴스를 확인해주세요.
2. 포트폴리오에 시험용 보유 기록을 등록하고, 무엇을 점검해주는지 설명해주세요.
3. 특정 회사나 분야에 투자가 몰려 있는지 확인하고, 관련 뉴스로 이동해주세요.

별도 브라우저 프로필의 시험 기록을 사용한다. 실제 계정 기록을 지우거나 바꾸지 않는다. 가격이 없는 종목은 가격 미확보 안내를 이해했는지 기록한다. 비중 계산이 불가능한 상태를 집중도 점검 성공으로 처리하지 않는다. 가상 예시를 사용했다면 개인 기록 등록과 구분해 적는다.

## 실제 확대·키보드·스크린리더

PC 브라우저 설정에서 실제 확대를 200%로 바꿔 기업 탐색, 자산 등록, 점검 결과, 계정 화면을 확인한다. 가로 스크롤 때문에 주요 행동이 가려지는지, 폼 오류와 닫기·저장 버튼에 접근할 수 있는지 적는다. CSS 글자 크기만 바꾼 검사는 이 확인을 대체하지 않는다.

마우스 없이 Tab/Shift+Tab/Enter/Escape로 검색→종목 선택→등록 폼→저장 또는 취소를 이동한다. 초점이 보이는지, 모달 내부에 유지되는지, 닫았을 때 열었던 버튼으로 돌아오는지 확인한다.

Windows의 NVDA 또는 사용 가능한 실제 스크린리더로 제목→검색→검색 결과→폼 이름과 오류→점검 결과 순서를 읽는다. 아이콘만 있는 버튼 이름, 로딩·오류 전달, 모달 닫기 접근을 확인한다. 모바일 웹을 확인했다면 기기·스크린리더를 별도로 적는다. 데스크톱 검사를 Android TalkBack 결과로 기록하지 않는다.

| 확인 | 도구·브라우저 / 실제 결과 / 수정·재확인 |
|---|---|
| PC 실제 200% 확대 | 2026-10-11 Chromium151 격리 프로필 native zoom=2 자동 검사. CSS viewport1366→683, 빈 홈/등록/점검/탐색/계정 가로 넘침0. CSS 글자 확대가 아님. 실제 사람의 읽기 편의 관찰은 미확인. native-zoom-local-20261011.json 참조 |
| PC 키보드 전체 흐름 | 미확인 |
| 실제 스크린리더 읽기 순서·폼·오류·모달 | 미확인 |
| 모바일 웹 첫 이용 흐름 | 미확인 |

자동 키 입력으로 등록 열기·검색 선택·수량 초점·검증 오류·취소 확인을 검사했다. 취소 뒤 BODY로 초점이 빠지는 문제를 발견해 등록/수정 버튼을 기억하고 확인 모달 종료 후 복귀하도록 수정했다. 실제 사람의 Tab 전체 순서와 스크린리더 결과를 대신하지 않는다.

## 완료 처리

실제 관찰 결과를 채우고 발견한 문제를 수정한 뒤 해당 흐름을 다시 확인한다. 관찰만 요청했거나 자동 검사가 통과했다는 이유로 WEB-38을 닫지 않는다. 보고에는 막힌 화면·행동과 안내 문구만 포함하면 된다. 전체 화면 녹화나 계정정보 제출은 필요 없다.

# 개인 투자 점검과 초기 사용자 검증

2026-10-14. FireWatch의 첫 사용과 재방문 이유를 실제 보유 기록에서 찾는다.

## 대상과 가설

초기 대상은 국내·미국 주식과 ETF를 함께 보유하면서 구성을 쉽게 점검하고 싶은 개인 투자자다. 시세·뉴스·게임의 기능 수보다, 보유 기록을 등록한 뒤 유용한 발견을 하고 다시 점검하는지를 확인한다. 단기 매매 신호나 수익 예측을 제품의 약속으로 삼지 않는다.

## 구현한 첫 화면

- 전체 또는 일부 평가금액, 가격·환율이 확인된 종목 수, 시세·환율 기준 날짜를 표시한다. 일부 평가금액은 확인된 자산과 현금의 합계이며 전체 자산 평가액이 아니다.
- 가장 큰 보유 종목 비중, 등록된 같은 ETF 지수명, 개별주식의 기록된 분야, 거래 통화 중 최대 세 가지를 보여준다. ETF 구성 종목 중복이나 실제 환율 노출을 계산했다는 표현은 사용하지 않는다.
- 수량 수정 버튼으로 실제 매수·매도 이후 기록을 유지하기 쉽게 한다. 여기서 수량을 바꿔도 실제 주문은 발생하지 않는다.
- 보유 종목 관련 소식을 위쪽에 배치한다. 서버 카탈로그의 이름·별칭과 기사 제목·설명을 대조하며 최신 200개 저장 기사와 최근 브리핑에서 최대 10개를 연결한다. 첫 화면에는 최신 두 개를 보여준다. 의미 분석이나 주가 변동 원인 판정이 아니다.
- 애플은 공식 [투자자 FAQ](https://investor.apple.com/faq/default.aspx)의 AAPL 식별자를 확인해 한국어·영문 검색 목록에 추가했다. 분야는 서비스 내 탐색 묶음이며 거래소의 공식 산업 분류가 아니다. 기존 회사의 확인일과 편집 자료는 보존한다.

## 점검 기준 저장

`첫 점검 마치기` 또는 `이번 점검 마치기`를 누르면 서버가 현재 보유 내역, 평가값, 시세 날짜, 환율 날짜와 연결된 기사 링크를 비교 기준으로 저장한다. 화면 진입만으로 이전 기준을 덮어쓰지 않는다.

- `PUT /api/portfolio/review`는 현재 포트폴리오 `version`만 받는다. 클라이언트가 비교 금액을 전달하지 않으며, 서버에서 계산한 자료를 저장한다.
- 기준은 기존 소유자 포트폴리오 행의 `review_json`에 저장한다. 같은 계정의 웹·앱에서 공유하고, 계정 포트폴리오 삭제 시 함께 삭제된다. 추가 사용자 행동 추적이나 외부 분석 도구 전송은 구현하지 않았다.
- 점검 기준을 저장해도 보유 종목·수량·가격·현금과 기록 편집 시각은 바꾸지 않는다. 동시 변경을 막기 위한 버전은 증가하며, 이전 버전으로 저장하면 409를 반환한다.
- 보유 기록의 추가·삭제·수량·가격·정보·현금 수정과 비중 차이를 구분한다. 비중 차이는 `%p`로 표시하며 수익률이 아니다. 두 시점 모두 전체 평가 자료와 양의 총액이 확인된 경우만 비교한다.
- 일부 시세가 빠져도 점검 기준은 저장할 수 있다. 이때 기록과 날짜가 확인된 새 소식을 비교하고, 비중 변화율은 만들지 않는다.
- 새 소식 수는 현재 연결된 최대 10개 기사 중 이전 점검 뒤 발행됐고 당시 링크 목록에 없던 자료 수다. 모든 시장 소식의 수가 아니다. 발행일 미확인·미래 날짜는 새 소식으로 세지 않는다.

기존 서버 응답에 `reviewCheckpoint` 필드가 없으면 비교 저장 버튼은 표시하지 않는다. 일반 조회와 보유 등록 흐름은 사용할 수 있다.

## 출시 전 확인

1. 서버에 추가 SQL을 적용한다: `ALTER TABLE portfolios ADD COLUMN IF NOT EXISTS review_json TEXT;`. H2·PostgreSQL 초기화 SQL에 같은 변경이 포함돼 있다. 기존 포트폴리오와 시세를 지우지 않는다.
2. 서버 배포 후 현재 APK와 새 클라이언트의 조회·등록·409 충돌 처리, 서로 다른 계정의 점검 격리, 같은 계정의 웹·앱 점검 공유를 확인한다.
3. 2026-10-14 생성한 1.0.12/빌드17 APK로 실제 휴대폰에서 검색 키보드·뒤로가기·수량 수정·점검 저장·재실행을 확인한다. 점검 저장은 새 서버·스키마 배포 후 확인한다.
4. 실제 보유한 국내주식·미국주식·국내 ETF·미국 ETF로 평가값을 대조한다. 수량·가격 통화·시세 날짜·환율 날짜를 먼저 맞춘다. 증권 앱의 실시간 평가액과 수집 시세의 차이를 오류와 구분하고, 데이터가 빠진 이유도 확인한다.

로컬 API fixture와 H2 테스트는 실제 외부 시세 수집, 운영 DB 배포, 실기기 검증을 대신하지 않는다.

## 5~10명, 2주 초기 검증 제안

숫자는 작은 초기 검증을 위한 제안이며 업계 성공 기준이 아니다. 참여자 모집과 연락은 별도 진행한다. 계좌번호·로그인 정보·실제 금액 공유는 요구하지 않는다. 화면을 설명하지 않고 첫 작업을 관찰하되 개인 자료는 기록하지 않는다.

| 관찰 | 확인할 행동 | 기록 방식 |
|---|---|---|
| 첫 등록 | 설명 없이 보유 종목 2~3개를 등록하는지 | 시작·완료 시간, 막힌 문구, 도움 요청 |
| 첫 효용 | 새로 알게 된 점을 자기 말로 설명하는지 | 사용자 설명을 익명으로 요약 |
| 재방문 | 별도 사용 요청 없이 7일·14일 사이 다시 여는지 | 참여자 자가 기록·면담, 요청한 방문과 구별 |
| 기록 유지 | 실제 매수·매도 후 수량을 스스로 수정하는지 | 행동 여부와 어려운 단계만 기록 |
| 신뢰 | 누락 자료·날짜·ETF 비교 범위를 이해하는지 | 오해한 내용과 영향을 기록 |

점검 저장 버튼을 눌렀다는 사실만으로 효용이나 재방문을 입증하지 않는다. `무엇을 새로 알았나요?`, `다음에도 켤 이유가 있나요?`, `기존 앱보다 번거로운 점은 무엇인가요?`를 함께 확인한다.

첫 효용이 약하면 점검 내용을 수정하고, 기록 유지가 어려우면 여러 종목 입력·CSV 가져오기를 검토한다. 자발적 재방문 이유가 없으면 새로운 AI·게임·차트 기능을 늘리기 전에 대상 사용자와 해결할 문제를 다시 확인한다.

# BE-30 · WEB-19 실제 계정 최종 확인

실제 Google 로그인을 수행한 사용자 브라우저에서 확인한다. 개발자는 키·토큰·세션 원문을 받지 않는다. 별도 브라우저 프로필 또는 시크릿 창을 사용하면 기존 운영자 계정의 기기 연결과 충돌하지 않는다. 로그아웃/재로그인 동안 같은 창을 유지하고 사이트 저장소를 삭제하지 않는다.

## 일반 계정

1. 운영자 이외 Google 계정으로 `/account`에서 로그인한다. 로그인 전·후 화면을 구분한다.
2. 전체 메뉴·설정·내 계정에서 감사로그/수집 진단/운영자 푸시가 표시되지 않는지 확인한다.
3. `/audit-log` 주소로 직접 들어가도 감사 표나 상세 기록이 표시되지 않는지 확인한다.
4. 가능하면 개발자 도구 Network에서 로그인 후 자동 요청되는 `/api/operations/access`가 `403`인지 확인한다. 네트워크 전체 내보내기/HAR/요청 헤더 공유는 하지 않고 상태 코드만 알려준다. 비로그인 `401`과 실제 로그인 `403`을 구분한다.
5. 기존 관심 기업·포트폴리오의 표시를 확인한 뒤 **로그아웃** 버튼으로 해제한다. **계정 삭제**를 누르지 않는다.
6. 같은 계정으로 다시 로그인해 기존 기록이 같은지 확인한다. 기록이 없으면 보존 확인은 미검증으로 남긴다. 익명 상태에서 다른 기록을 표시하는 것을 계정 데이터 삭제로 오해하지 않는다.

## 운영자 계정

1. 운영자 계정으로 다시 로그인해 운영자 표시와 감사로그 접근이 가능한지 확인한다.
2. 로그아웃 후 운영자 메뉴가 사라지고 감사로그 직접 주소가 차단되는지 확인한다.
3. 같은 운영자 계정으로 재로그인해 기존 관심 기업/포트폴리오가 유지되는지 확인한다. 기록 없는 경우 보존 증거로 처리하지 않는다.

## 완료 판단

BE-30은 실제 일반 계정의 운영 진단 제한 결과를 WEB-19와 공유한다. WEB-19는 실제 운영자 접근 및 로그아웃/재로그인 기록 보존까지 확인해야 종료한다. 로컬 fixture 403/200·익명 운영401은 실제 Google 세션 결과를 대체하지 않는다. 실패하면 단계·화면 메시지·상태 코드만 기록하고 필요한 수정과 재검증을 진행한다.

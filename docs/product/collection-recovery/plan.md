# BE-30 수집 복구 운영 확인

기존 BE-30의 실제 수집·복구·운영자 수신을 검증한다. 새 BE 번호는 추가하지 않는다. 전체2669목록 자동 수집으로 범위를 확대하지 않고 보유/관심/추천 종목 대상과 회당 최대10요청을 먼저 대조한다.

예약 워크플로 활성·최근 호출 HTTP 결과, 운영 DB의 최근 작업/회로/장애/관측과 운영자 등록 여부를 함께 확인한다. HTTP200·triggered:true는 실제 수집 성공 증거가 아니다. 운영 집계는 읽기 전용·문장5초 제한·JSON 한 셀로 제공하며 개인정보/원본 뉴스/종목명/계정ID/토큰/제공처URL을 출력하지 않는다.

실제 실패 원인이 확인되면 필요한 코드만 수정하고 회귀/PG/CI/기존 과제 PR로 검증한다. 기록 삭제·실패 한도 초기화·무제한 재시도는 하지 않는다. 운영자 실수신은 사용자 기기의 테스트 알림 수신 여부로 확인한다. APK 빌드 보류는 유지한다.

사용자 테스트에서 HTTP500이 확인됐다. 모든 제공처 발송 실패를 IllegalStateException으로 던져 일반500으로 가리는 경로를 재현한다. 웹 푸시의 설정 누락/인증 거절/만료/제공처 실패를 안전한 코드로 집계하고 운영자 테스트에는503과 조치 안내를 반환한다. 로그에서 구독 URL과 예외 원문은 제외한다. 이는 진단 수정이며 실수신 복구를 완료했다고 판단하지 않는다.

추가 소스 검토에서 앱 발송 예외가 웹 발송까지 중단하는 경로를 확인했다. 채널별 예외를 안전하게 처리해 다른 채널 발송을 계속한다. 둘 다 실패하면 테스트503과 기존 outbox 실패 정책을 유지하고 예외만으로 구독/토큰을 삭제하지 않는다.

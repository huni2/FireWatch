# 게임 서버 계측 계획

BE-28 후속, BE-36 개발 단계. 첫 시작13.96초·다음 턴1.29초의 HTTP 관측을 서버/DB 시간으로 오인하지 않도록 게임 요청 안에서만 Hibernate JDBC 이벤트를 집계한다. 외부 비용/패키지·공개 진단 API·원장 변경은 추가하지 않는다.

기본 비활성 FIREWATCH_GAME_TIMING_ENABLED=true일 때 고정 행동명·성공/실패·IO 큐/서버 구간·JDBC 연결 획득/준비/실행 시간/횟수·프로세스 uptime만 Render 서버 로그에 남긴다. SQL/바인딩/기기/세션/종목/가격/예외 메시지는 기록하지 않는다. 단일 JDBC 스레드 구간에서 ThreadLocal을 시작/해제하고 Hibernate SessionEventListener는 기존 JPA 경로를 관찰한다. DataSource/Connection 래핑이나 잠금/트랜잭션 변경은 하지 않는다.

각 시간은 네트워크 왕복을 포함한 드라이버 관측이며 DB CPU/개별 COMMIT 시간과 다르다. 준비/연결 등 이벤트 구간은 겹칠 수 있으므로 단순 합계/CPU 잔여시간을 계산하지 않는다. 서버 타이머는 컨트롤러 진입부터 DTO 반환까지만 포함하고 응답 직렬화/전송과 시작 전 기동은 포함하지 않는다.

단위/실제 H2/전용 PostgreSQL에서 활성/비활성·성공/예외 정리·스레드 격리·JPA 등록·게임 가격/원장/동시성 보존을 확인한다. CI/PR 머지 후 운영 배포·플래그 설정 및 실제 로그 대조는 BE-28에 남긴다. 확인 없이 속도 개선을 주장하지 않는다. APK/EAS 빌드0.

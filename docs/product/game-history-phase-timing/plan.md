# 게임 최초 조회 지연을 단계별로 확인

BE-28의 실제 HISTORY 로그는 첫 서버8,665.392ms/재조회338.617ms, SQL176.611/167.377ms, 연결169.520/0.023ms다. 첫 uptime285,565ms로 JVM 기동 직후 요청이라고 단정할 수 없다. 현재 계측만으로 초기화·ORM 결과 처리·트랜잭션 시간을 구분할 수 없다.

게임 HISTORY의 repository 반환까지, 규칙 선택/최초 로딩, 그래프 계산을 고정 이름의 숫자 구간으로 기록한다. 규칙 선택은 시작/기존 서비스 경로에도 적용한다. 기존 옵션이 꺼지면 단계 계측도 꺼진다. SQL·입력·식별자·예외 메시지를 추가하지 않는다. 게임 규칙/평가/DB/잠금/API는 유지한다.

단계는 서비스 안쪽의 구간이다. repository에는 JDBC가 포함되므로 합산하지 않는다. 서비스 바깥 트랜잭션 진입/종료·직렬화는 이 단계에 포함되지 않는다. 실제 원인은 새 운영 로그 이후 판단한다.

# 게임 시작·주문의 불필요한 DB 조회 축소

BE-28 운영 로그 START 서버1168.127ms/SQL736.534ms(4회), TRADE1620.570/914.137ms(5회), NEXT_TURN1485.291/929.484ms(4회). 규칙 선택은 각0.947/0.052/0.059ms로 주 병목이 아니다. SQL 시간은 통신·DB·잠금 등을 포함하며 개별 SQL의 비용이나 리전 차이는 이 로그만으로 확정하지 않는다.

새로 INSERT한 세션의 원장은 비어 있으므로 첫 snapshot에 빈 원장을 전달한다. 기존 게임 이어하기는 저장 원장을 그대로 조회한다. 주문은 잠근 세션의 원장을 한 번 읽어 requestId 중복 확인과 현재 턴까지의 현금/보유량/응답에 공유한다. 미래 턴 기록은 평가에서 제외하되 중복 요청 검사는 기존과 같이 전체 세션 범위를 유지한다.

세션 잠금·멱등 충돌·낡은 턴 거절·현금/수량 검증·원장 INSERT·감사로그·트랜잭션 경계를 유지한다. DB 스키마/규칙/시세/캐시/연결 풀·Android 빌드는 변경하지 않는다. NEXT_TURN은 중복 조회가 없어 이번에 변경하지 않는다.

완료 기준은 실제 SQL 횟수 감소와 동일한 평가/원장/멱등/거절 결과의 H2·PostgreSQL 검증이다. 운영 속도 개선은 배포 후 실측 전까지 주장하지 않는다.

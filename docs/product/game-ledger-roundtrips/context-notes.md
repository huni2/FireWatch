# 결정과 관찰

전체192검사 실패0/오류0/기존 제외1로 성공했다. H2 실제 이벤트에서 새 시작3·주문4·재전송3 SQL을 확인했고 동일 요청/다른 기대 턴의 재전송은 한 원장·동일 현금/수량, 수량 충돌409 뒤 이어하기 원장/현금/수량 보존도 확인했다. 미래 기록은 requestId 검사에 포함하면서 현재 평가/거래 목록에서 제외하는 단위 회귀가 통과했다. PostgreSQL 실제 이벤트는 기존 GameTimingIntegrationTest CI 선택에서 확인한다.

첫 전체192검사에서 새 잔액 보존 테스트1곳 실패. 신규 INSERT 직후 quantity1/재조회quantity1.0000·total scale 차이 때문에 data class equals가 실패했으며 값/체결 ID는 같았다. SQL 새 시작3·주문4·재전송3은 이미 확인됐다. 테스트에서 숫자 scale을 정규화하고 다시 검사한다. 서비스 DTO/가격/원장을 정규화하거나 수정하지 않는다.

사용자의 실제 시작·거래·다음 턴3줄을 수신했다. 모든 요청은success이고 연결1회·약182ms다. SQL 여러 번의 누적 시간이 길다. 코드상 잠금 조회·거래/턴 저장·감사로그는 필요한 처리이며 제거하지 않는다. 비어 있는 신규 원장 조회와 주문의 별도 requestId/원장 조회는 같은 결과를 유지하며 줄일 수 있다.

전체 세션 원장 조회는 기존 currentTurn 이하 조회에 비해 비정상 미래 기록도 읽을 수 있다. 현재 턴 평가에는 필터하고 requestId 검색에는 포함해 기존 중복 요청의 전체 세션 의미를 보존한다. 요청 ID 형식 검사는 조회 전 유지한다. 운영 SQL 원문/사용자 로그는 추가하지 않는다.

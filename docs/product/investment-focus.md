# FireWatch 핵심 흐름과 기업 점검

FireWatch의 중심은 시장 자료를 이해하고 개인 투자 기록의 구성을 점검하는 서비스다. 가상투자는 독립된 연습 메뉴이며 순위는 게임 안에서만 제공한다. 홈과 기업 탐색에서 게임 경쟁을 우선 소개하지 않는다.

## 이번 구현

- 홈 `내 기업 점검`: 관심 종목과 저장된 개별주식 보유를 중복 제거해 6개씩 표시한다. 다음 페이지는 클라이언트에서 전환한다.
- 기업 이름, 관심/보유 표시, 저장된 포트폴리오와의 비교, 검증된 추천 이유/위험, 분석 자료의 관련 기사 최대 2개를 보여준다.
- 기사에는 분석 기준 날짜를 표시한다. `저장된 뉴스`는 회사명을 뉴스 검색에 전달하며 기존 날짜 필터와 보관 자료를 사용한다. 분석 기사와 최신 뉴스 목록을 구별한다.
- 종목 화면에서 가격·차트·뉴스를 확인한 뒤 저장된 추천 근거와 내 보유를 비교하고 포트폴리오 점검으로 돌아갈 수 있다.
- 웹과 모바일은 shared/investment-focus.ts의 동일한 연결 규칙을 사용한다. 모바일 홈 점검은 새로고침으로 관심 기업을 다시 읽을 수 있다.

## 정확성과 비용

추천 후보는 회사의 정확한 이름/카탈로그 별칭과 저장 기사 링크·이유·위험이 모두 확인될 때만 표시한다. 근거가 없는 후보나 계열사 이름 유사성은 추천으로 이어 붙이지 않는다. 조회 실패는 추천 없음과 구별한다.

비중은 매입원금과 현금 기준이며 실시간 평가 비중이 아니다. 같은 분야 비교는 등록한 개별주식과 카탈로그 분야만 비교한다. ETF 내부 구성 종목은 분석했다고 표현하지 않는다. 회사 자료가 없는 경우 보유 여부만 안내한다.

홈은 기존 설정·추천 API 각 1회와 부모가 읽은 포트폴리오를 사용한다. 기업 수가 늘어도 가격/뉴스/AI API를 기업마다 추가 호출하지 않는다. 새 서버·유료 서비스·DB 초기화는 없다. 기존 API 클라이언트의 제한된 읽기 재시도 정책은 그대로다.

## 검증과 남은 일

웹 fixture에서 추천 근거·위험·보유 비중, 근거 없는 후보 숨김, 7기업 페이지 전환, 회사 시세→보유 점검 및 회사명 뉴스 검색, 빈 목록과 조회 실패를 확인했다. 1366/1920/390/360px 가로 넘침·JS 오류·운영 쓰기 없음. 웹 build/lint, 모바일 타입/린트를 확인한다.

모바일 네이티브 설치에서 탭 이동·새로고침·뉴스 링크는 새 APK에서 검증해야 한다. 기존 설치 앱에 자동 반영됐다고 표현하지 않는다.

후속: 관심 기업 뉴스의 날짜별 변화, 추천 분석 이력과 내 보유의 시간별 비교, 카탈로그 확장 및 출처 갱신. 가격 등락의 실제 인과 관계를 AI 문장으로 단정하지 않는다.

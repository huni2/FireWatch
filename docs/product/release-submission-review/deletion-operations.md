# 계정·기기 자료 삭제 요청 운영 절차

BE-21의 운영 절차 초안이다. 실제 요청 처리 이행·처리기간·보관기간이 확정됐다는 뜻은 아니다. 공개 요청 경로는 `/privacy#delete-account`, 연락처는 `powerhch@gmail.com`이다. 사용자 비밀번호·Google ID 토큰·Bearer 인증 토큰·API 키·계좌번호를 받지 않는다.

## 접수와 본인 확인

1. 앱/웹에서 직접 삭제할 수 있는 사용자에게 계정 삭제 경로를 안내한다. 운영자 실제 계정으로 삭제 시험하지 않는다.
2. 이메일 요청에는 삭제하려는 범위(계정 공유 기록/기기 게임/익명 기록), 이용 플랫폼, 답변 가능한 연락처만 우선 받는다. 이메일 주소만 같다는 이유로 타 계정 기록을 삭제하지 않는다.
3. 계정 소유와 기기 소유를 별도로 확인한다. 로그인 가능한 계정은 기존 인증된 세션과 연결 기기 경로로 확인한다. 접근할 수 없는 기기는 본인 확인 방법을 먼저 정하며 게임 목록·이메일 일치만으로 소유를 확정하지 않는다.
4. 요청 대상 기기 관계를 삭제 **전에** 확인한다. 현재 계정 삭제는 device_links를 제거하므로 삭제 후 계정만으로 과거 기기 게임을 찾을 수 없을 수 있다. 과거 연결 해제 기기의 자동 복원/포괄 삭제는 구현되지 않았다.
5. 확인에 필요한 식별 자료는 비공개 운영 저장소에 최소한으로 보관한다. GitHub 이슈에는 작업 단계·집계·결과만 남기고 이메일/기기 ID/원문/백업을 올리지 않는다.

## 대상별 현재 처리와 남은 일

| 범위 | 구현된 처리 | 운영자가 별도로 확인할 것 |
|---|---|---|
| 계정·공유 설정·포트폴리오/이력 | AuthController 인증 후 AuthService.deleteAccount 트랜잭션 | 폐기 가능한 시험 계정으로 실패 시 롤백/성공 후 재조회 검증 |
| 연결 기기·세션 | 모든 계정 세션 폐기·device_links 삭제 | 다른 연결 기기에서도 기존 세션이 거절되는지 확인 |
| 문의·공지 숨김·순위/우승자 | app_users 외래키 cascade | 실제 운영 스키마와 공개 순위/본인 문의 재조회 대조 |
| 현재/과거 기기 게임·가상 체결·가격 | 계정 삭제에 포함되지 않음 | 소유 확인 후 게임 부모/연관 행 범위와 순위 FK를 대조. 검토·승인된 처리 전 운영 삭제 SQL을 실행하지 않음 |
| 별도 익명 설정/보유 | 계정 공유 행 삭제와 다름 | 계정 연결 시 공유 행과 합류하지 않은 기기 자료의 소유 확인 |
| 감사 기록 | 자동 만료/개별 계정 cascade 없음 | 조사 목적·기간·개인 자료 범위 결정. 보안 증거와 인증 원문을 같은 이유로 무기한 보관하지 않음 |
| 덤프·제공업체 로그/백업 | DB 계정 삭제로 파일이 자동 수정되지 않음 | 실제 보관 위치·삭제/만료 가능성·계약·복구 전 요청 재적용 |
| 시장 뉴스·시세·공공 분석 | 개인 계정 삭제와 별개 | 계정 관련 자료와 공공 시장 자료를 구분 |

기기 게임은 서버 기록이며 ‘가상’ 또는 ‘익명 ID’만으로 비개인정보라고 판정하지 않는다. 특정 자료를 정당한 사유로 남겨야 하면 범위·사유·기간을 사용자 안내와 실제 운영에 맞춘다. 삭제 요청을 받았다는 이유로 공공 뉴스·전체 게임·모든 감사 기록을 일괄 삭제하지 않는다.

## 처리·복구·회신

접수 확인 시 본인 확인과 필요한 추가 정보, 예상 처리 시점을 안내한다. 확인이 지연되면 사유와 다음 확인 시점을 안내한다. **현재 확정된 처리기간은 없다.** 아래 체크리스트의 기간 결정과 공개 안내 반영 후 운영한다. 임의 ‘7일 이내’ 등을 현재 약속으로 안내하지 않는다.

비공개 처리 기록은 다음 최소 항목을 사용한다. 실제 요청의 개인 자료를 이 Markdown에 채우지 않는다.

| 항목 | 기록할 내용 |
|---|---|
| 요청 번호·접수/회신 시각 | 개인 식별값을 포함하지 않는 운영 요청 번호 |
| 확인 범위·방법·완료 시각 | 계정/기기별 소유 확인 상태. 인증 원문은 기록하지 않음 |
| 처리 범위 | 공유 기록/기기 게임/익명 기록/감사/백업 구분 |
| 전후 검증 | 대상 행 수·조회 결과·세션 거절 등, 원문 대신 집계 |
| 보관 예외 | 자료 종류·사유·기간·접근 제한·사용자 안내 |
| 백업/업체 후속 | 실제 처리 여부·복구 후 재삭제 적용 대상 |
| 완료/추가 확인 회신 | 처리한 자료·남은 자료·이유·다음 시점 |

백업에는 개인 기록과 로그인/푸시 정보가 포함될 수 있다. 복구 전에 삭제 요청 목록을 비공개로 대조하고, 복구 DB에 재적용하고 세션/푸시를 폐기한다. 기록을 이행하지 못한 복구 DB를 운영으로 전환하지 않는다. [기존 백업 절차](../../deployment/data-preservation.md)를 따른다.

## 코드의 삭제 실패 안전성 확인 (2026-10-10)

AccountSessionIntegrationTest의 H2 전용 시험에서 최종 app_users DELETE를 외래키로 차단했다. 기존 오류 계약은409 CONFLICT이며, 실패 후 공유 관심/포트폴리오/이력/문의/공지 숨김/기기 연결/세션 행이 모두 전후 동일하고 두 기기의 기존 세션이 유효함을 확인했다. 시험 제약을 제거한 뒤 같은 세션으로 재시도하면 공유 기록과 세션이 삭제되고 두 기기 세션이 거절된다. 별도 기존 검사는 다른 계정 보존도 확인한다. 의도된 실패 감사 기록은 보유 자료 롤백과 별개이며 감사 전체가 되돌아간다고 주장하지 않는다.

이 결과는 실제 운영 계정을 삭제했거나 기기 게임/백업 삭제까지 구현한 근거가 아니다. 성공/실패를 포함한 실제 운영 삭제 이행은 위 체크리스트에 남긴다.

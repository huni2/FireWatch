# 공식 회사 정보 갱신 절차

운영 중 API가 외부 회사 목록을 반복 다운로드하지 않는다. 공식 원본을 확인하고 스냅샷 차이를 검토한 다음 GitHub PR·검증·배포로 갱신한다. 원본 확인 주기는 주1회를 기준으로 하고, 사명 변경을 알게 된 경우 추가 확인한다. 이는 자동 예약 작업이 아니다.

1. KIND KOSPI·KOSDAQ 원본 두 파일을 확보하고 실제 확인 날짜로 생성한다. 명령과 원본 검증은 [갱신 비교 안내](../catalog-refresh-diff/usage.md)를 따른다.
2. 추가·이름·업종·누락 목록을 검토한다. 기존 내용과 다른 스냅샷에는 이전보다 나중인 확인 날짜를 사용한다. 같은 날짜 자료의 내용 교체는 DB 갱신 근거로 삼지 않는다.
3. PR에서 공식 자료와 생성 리소스를 함께 검토하고 H2·PostgreSQL CI를 통과시킨다.
4. 서버 배포 시 없는 코드는 기존 방식으로 추가한다. 기존 행은 마지막 공식 적용값과 이름·검색 문자열·전체 메타데이터·분류·확인일이 모두 같은 경우에만 다음 날짜 자료로 갱신한다.
5. `catalog_refresh baselined=… updated=… preserved=…` 로그와 공개 회사명·초성 검색을 대조한다. 로그는 집계값이며 모든 시세/투자 기록 보존 검증을 대신하지 않는다.

처음 이 기능을 배포할 때는 현재 공식 자료와 완전히 같은 행에만 기준값을 설정한다. 이미 편집됐거나 이전 자료만 남아 있어 기준을 확인할 수 없는 행은 보존한다. 큐레이션31개는 이 공식 갱신에서 제외한다. 검색 별칭 추가·편집 충돌 해결은 검토 후 별도 작업으로 진행한다. 사명이 바뀌어도 내부 종목코드는 유지하고 과거 이름을 자동 별칭으로 만들지는 않는다.

다음 원본에서 빠진 회사는 삭제하지 않는다. 상장폐지 여부와 시장 이동은 별도 확인이 필요하며 보유/게임의 코드를 자동 이전하지 않는다. 가격·시세 시각·뉴스·보유·게임 기록은 갱신 대상에 포함하지 않는다. 서버 시작은 검토된 로컬 리소스만 읽으므로 외부 제공처 실패에 따른 재시도가 없다.

BE-43은 갱신 정책과 서버 적용 경로를 구현한다. 이번 커밋은 실제 회사 스냅샷 내용을 변경하지 않는다. 해외 종목/ETF 확대·실제 운영 부하 검증은 BE-22에 남긴다. APK/EAS 빌드는 실행하지 않는다.

# BE-44 실제 카탈로그의 PostgreSQL 검색 규모 검증

BE-22 기존Issue#43 재개(2026-10-10). 검색/PG/페이지 개선 완료 항목은 반복하지 않고 운영 집계·출시 범위를 마무리한다. 이전 여러SELECT 결과의 마지막 인덱스 표만 수신됐으므로 읽기 전용 집계를 JSON 한 셀로 제공한다. 개인정보/종목별 원본/키를 출력하지 않으며 기존5초 statement_timeout을 유지한다. 공식 기준값·분야/국가별 시세 건수·비정상 시세·DB/테이블/인덱스 공간을 기존 SQL과 같은 정의로 집계한다. 범위는 사용자 응답 전 임의 보류하지 않는다. 공개 GET은 최대10건/동시2건·재시도/외부 검색0. 실제DB 결과는 사용자 제공 전 미확인 유지·새 과제/운영 쓰기/APK0.

## 기존 BE-22 운영 확인 이어가기 (2026-10-09)

새 과제 번호 없이 운영 공개 API의 동시 조회를2건씩 총10건만 실행한다. 조회 결과의 일관성·시세 유무·HTTP 시간을 기록하며 외부 제공처 호출이나 자동 재시도·운영 쓰기는 하지 않는다. 운영 DB의 공식 기준값/실제 시세 행수/테이블·인덱스 용량은 읽기 전용 집계 SQL로 별도 확인한다. 공개 응답을 DB 전체 통계로 확대하지 않는다.

공식 한국 회사2651개와 큐레이션31개를 합친2669상품을 전용 테스트 DB에서 검증한다. 합성3000개 검사는 유지하고 실제 이름/초성·짧은 검색·필터·페이지에 대해 서비스가 실행하는 COUNT/목록 SQL의 계획과 시간을 수집한다.

PostgreSQL CI에서 현재 검색을 먼저 측정한 다음 전용 DB에만 pg_trgm 후보 인덱스를 생성해 같은 SQL을 대조하고 삭제한다. 운영 스키마와 무료 운영 DB에는 인덱스를 자동 추가하지 않는다. 정렬·파싱·왕복까지 포함한 서비스 시간과 SQL 실행 시간을 구분한다. 저장 공간은 전용 DB의 실제 카탈로그/후보 인덱스 크기로 기록한다. CI 단일 프로세스 측정은 운영 동시 부하 결과가 아니다.

GitHub Issue/PR·전체 회귀·PostgreSQL·복원 검사와 결과 문서를 남긴다. 실제 회사 자료·시세·운영 DB·APK/EAS 빌드는 변경하지 않는다.

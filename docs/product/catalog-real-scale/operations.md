# BE-22 운영 집계 확인

Supabase 프로젝트의 SQL Editor에서 [읽기 전용 집계 SQL](operator-summary.sql)을 한 번 실행한다. 운영 DB의 이름·종목별 가격·사용자 계정·포트폴리오·뉴스 원문·토큰은 출력하지 않는다. 읽기 전용 트랜잭션과 문장별5초 제한으로 실행하며 데이터/스키마를 바꾸지 않는다. 실패하면 반복 실행하지 않고 오류를 확인한다. 시간 초과로 트랜잭션이 실패한 경우 `ROLLBACK;`으로 종료한다.

공유할 결과는 기준값/검색 열 집계, 종류·국가별 시세 집계, 전체 시세 집계, 용량, 인덱스별 용량의5개 결과다. 접속 문자열·API 키·계정 정보는 필요 없다. 기준값 개수가 공식2651개와 같아야 한다고 강제하지 않는다. 기존 편집/큐레이션/공식 목록 중복 때문에 적용 대상은 달라질 수 있다. 기준값 존재는 현재 행이 공식 자료와 같다는 증거도 아니며 갱신 중 편집 보존 여부는 별도 회귀로 확인한다.

가격이 저장된 회사 수와 전체 시세 행수는 구분한다. 카탈로그 밖의 시세도 기록이므로 지우지 않는다. oldest_quote_at/newest_quote_at은 제공처 가격 시각이며 수집 시각과 다르다. 오래된 값을 오늘의 값으로 다시 저장하지 않는다.

## 이번 공개 확인의 요청 예산

2026-10-09 확인은 동시에 최대2건·총10건의 GET이며 자동 재시도0회다. 도구 필드명 수정 전2건을 포함한 실제 요청은12건이다. 기존 `/api/catalog`은 저장 DB만 조회하고 외부 가격/목록 제공처를 부르지 않는다. 한 요청은 COUNT와 최대50행 목록 SQL의2회 조회다. 따라서 이번 성공한10건은 최대20개의 해당 SELECT, 수정 전2건 포함24개다. 운영자 SQL의 별도 집계는 이 숫자에 포함하지 않는다.

이는 작은 동시 기능 확인이다. 무료 서버의 최대 처리량·다수 사용자의 요청 상한·Supabase 할당량 준수나 운영 요금0원을 입증하지 않는다. 실제 DB 사용량과 제공처 수집 예산은 집계 결과 및 기존 수집 제한을 함께 대조해야 한다. 부하를 높이거나 예약 실행·무제한 재시도를 추가하지 않는다.

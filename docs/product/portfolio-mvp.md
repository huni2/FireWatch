# FireWatch 포트폴리오 MVP

## 정체성과 흐름

검색 인프라 결정(2026-10-06): 사용자 요청으로 OpenSearch 도입을 보류한다. 기존 Cloudflare Pages + Render + Supabase를 유지하며 추가 유료 인프라 없이 PostgreSQL 기반 검색 개선을 다음 과제로 둔다. 현재 검색은 아직 기존 외부 API를 사용한다.

개인의 투자 목표와 보유 자산을 시장 맥락에 연결하는 투자 점검 앱. 첫 화면은 내 포트폴리오이며, 목표·기간·성향·계좌·월 투자금 → 자산 등록 → 저장 후 분석 → 투자 후보·상품 비교 → 추가 뉴스 → 투자 연습으로 이어진다. 단기 투자 메뉴는 분리한다.

## 이번 구현

- `GET/PUT /api/portfolio`: 기기/연동 계정별 저장. `version`이 다르면 409. 매 변경의 서버 스냅샷을 기록한다. 계정 삭제 시 포트폴리오와 변경 이력도 삭제한다.
- 매입원금 기준 자산 비중, 단일 자산·분야 집중, 입력한 동일 추종 지수 중복을 분석한다. ETF 구성 종목까지 분석하는 것은 아니다.
- 기간/성향별 규칙 기반 구성 초안과 월 투자금 배분 예시. 12개월 미만은 현금 중심 예시. 분석 버전 `portfolio-rules-v1`을 표시한다. 실적 예측이나 적합성 심사 결과가 아니다.
- 시세가 누락되면 전체 평가금액을 숨긴다. 환율은 최근 브리핑 기준이며 수익률은 가격 변동 기준으로 환차익을 계산하지 않는다. 자산별 시세 시각을 보여준다.
- `GET /api/news`: 브리핑과 독립된 뉴스 저장소. 30분 간격 수집, 링크 중복 제거, 제목 중복 제거. 포트폴리오 관련 뉴스는 이름/티커 문자열 일치 방식이다.
- 등록 종목은 한국 시간 07시 이후와 16시 이후 수집 슬롯으로 묶는다. GET 요청은 외부 시세 API를 호출하지 않는다. 서버 재시작 후 완료 슬롯을 확인한다. 외부 폴링에서도 수집을 호출한다.
- 투자 후보는 기존 아침 브리핑의 공통 시장 후보다. 개인별 종목 점수/추천 엔진은 아직 아니다. ETF 비교는 직접 입력한 지수·통화·지역과 확인 항목을 제공한다.
- 가상투자 게임은 최근 최대 90개 브리핑 날짜를 섞는 별도 게임이다(2026-10-07 사용자 요구 정정). 미래 가격 대체를 금지하고 확인된 가격을 세션·턴·자산별 DB에 저장한다. 주문 미리보기/단가 확인, 세션 행 잠금, 활성 세션 유일성, 재시도에도 같은 요청 ID, 예상 턴 검증을 적용한다. 보유 수량·평가액·턴 변화액과 체결 단가·총액을 제공한다. 가격 누락은 null 평가이며 다음 턴 보유 가격이 없으면 턴을 유지한다. 첫 턴 대비 코스피와 집중/현금 비중 회고는 무작위 게임의 결과다. AI 후보가 없는 날짜에도 빈 이유를 표시한다.
- 설정은 변경 필드만 전송/반영한다. 푸시 전체 실패 시 당일 완료 표시를 하지 않는다. 공개된 `legacy-owner-device`는 거부한다. 감사로그에서 기기 ID도 마스킹한다.
- 웹/모바일 공유 타입·라벨·비교 항목을 `shared/investing.ts`에 두며 네트워크 시간 제한, 재시도, 백그라운드 복귀 갱신, 저장 실패 피드백을 추가한다.

## 운영/출시 전 남은 작업

2026-10-07 최종 게임 변경: 새 게임의 뉴스·지표·가격·픽·회사는 모두 가상이다. 시드 기반 24턴과 시장/업종 사건으로 상태를 생성하고 외부 뉴스·시세·AI 요청을 하지 않는다. 주문 금액은 클라이언트에서 즉시 계산하며 체결 검증은 서버에서 수행한다. 기존 과거 자료 게임만 아래 가격 누락/조회 범위 제약에 해당한다. 기존 기록은 삭제하지 않고 새 가상 게임으로 전환 시 종료 보관한다. simulation_seed additive SQL을 적용해야 한다.

실제 뉴스 메뉴는 별개의 보관함이다. from/to/q/page/size로 독립 RSS와 과거 브리핑 기사까지 검색하며 제목·설명 문자열 기준이다. 과거 데이터를 삭제하지 않는다. 기존 RSS가 수집한 범위만 검색할 수 있고 수집 전 기사, 원문 전체, 자동 종목 별칭·의미 검색은 제공하지 않는다.

1. 운영 서버에서 기존 공개 소유자 ID 접근을 차단했다. 설정의 관리 키 기반 이전 API는 기존 설정 행과 게임 기록을 새 기기로 연결하며 현재 기기에 데이터가 있으면 덮어쓰지 않는다. 실제 소유자가 해당 브라우저에서 이전해야 하고 자동 이전은 하지 않았다. 기존 기록은 삭제하지 않았다.
2. 현재 기기 ID는 익명 접근 자격으로 사용한다. 계정 세션 인증·갱신·해지와 관리자 감사로그 권한을 출시 전에 구현한다. 현재 감사로그 API는 공개 상태다.
3. 운영 PostgreSQL에 추가 스키마를 적용한 서버가 정상 기동했고 실제 저장·게임·뉴스 조회를 검증했다. 배포 전후 브리핑 45건과 연결 기사 775건이 유지된다. 별도의 백업 복원 훈련 및 모든 스키마 권한의 독립 감사까지 수행한 것은 아니다.
4. 뉴스/시세 제공처의 서비스 이용·재배포 조건을 확인한다. 현재 수집은 무료 제공처에 의존하며 SLA나 영구 무료를 보장하지 않는다. 실제 상품 메타데이터와 비용 비교 데이터는 아직 수집하지 않는다.
5. 수집 작업 임대와 카테고리 회로를 DB에 저장하고 상한 재시도·감사로그·화면 안내·운영자 푸시 대기열을 구현했다. 실제 운영자 등록과 푸시 수신, 거래소 휴장일·미국 서머타임·확정 종가 판별 및 데이터 백업·보관 정책의 운영 검증은 남았다. 늦게 등록한 종목은 다음 슬롯까지 시세가 없을 수 있다.
6. 게임 금/해외주식은 게임 단가 숫자를 사용한다. 실제 원화 환산, 수수료·세금·분배금·공매도 증거금은 반영하지 않는다. 새 게임에는 한 턴의 가상 사이드카/종목 거래정지 규칙이 있으며 실제 거래소 규정과 다르다. 날짜는 무작위이며 기존 덱을 변경하지 않는다. 개별 종목은 6개월 조회 범위 안에서 해당 날짜 이전 7일 이내 가격만 허용하므로 자료가 없으면 주문/다음 턴이 제한된다. game_price_snapshots SQL도 운영 DB 사전 검증에 포함한다.
7. 설정 동시 저장의 행 잠금/버전, 채널별 푸시 영수증·부분 실패 재시도, 관심 종목 빠른 연속 편집의 요청 직렬화를 보강한다.
8. 실기기에서 저장/재실행/백그라운드 복귀/알림/Google 연동/삭제를 확인하고 새 네이티브 모듈 `expo-crypto`를 포함한 Android 빌드를 만든다. JS 번들 검증은 설치/스토어 심사를 대신하지 않는다.
9. 개인정보 처리방침·Play Data Safety·금융 기능 선언을 현재 기능에 맞춰 재검토한다. 기존 제출 문서는 브리핑 앱 기준이므로 자동으로 그대로 사용하지 않는다.

## 2026-10-07 남은 게임 작업 완료

자산별 턴 손익 기여, 가상 사이드카(지수 주문 한 턴 제한), 가상 종목 거래정지(매매 제한/직전 평가 가격 유지), 차단 이유/해제 조건을 웹·모바일에 표시한다. 서버에서도 주문을 검증한다. 모바일 주요 화면의 라이트·오렌지 표면/간격/타이포와 빈 상태/검색 오류를 개편했다. SSE는 속도 개선 목적에 맞지 않아 게임에는 도입하지 않았다.

## 검증 명령

```text
backend: .\gradlew.bat test --offline

```

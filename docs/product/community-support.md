# 사용자 피드백·공지 운영

## 첫 버전

웹 `/community`와 Android 설정의 공지·의견 화면은 같은 서버 자료를 사용한다. 문의는 Google 로그인 후 접수하며 본인 계정과 검증된 운영자만 읽는다. 관리에는 Google 운영자 계정 세션이 필요하며 예약 작업의 서버 키만으로는 접근할 수 없다. 관리 화면은 웹의 운영자 관리 탭이다. Android에서도 웹 관리 화면을 사용할 수 있지만 네이티브 관리 편집 화면은 별도다.

오류 신고/개선 제안/기타, 5~3000자 본문, 클라이언트 버전과 접수 화면 경로를 저장한다. 포트폴리오·토큰·쿼리 문자열은 자동 첨부하지 않는다. 같은 요청 UUID 재전송은 같은 문의를 반환한다. 계정별 시간당 3건을 DB와 잠금으로 제한한다. 상태는 접수/확인 중/해결/보류이며 답변은 본인의 내 문의에서 새로고침한다. 초기 조회는 내 문의 최대 100건, 운영 조회는 50건씩 페이지다. 계정 삭제 시 문의·답변·공지 숨김은 FK CASCADE로 삭제한다.

운영자 푸시 수신자는 기존 collection_operator 설정을 사용한다. 새 문의는 영속 outbox 필드에 대기하고 기존 예약 폴링에서 발송한다. 즉시 발송을 보장하지 않는다. 실패는 최대 3회·60분 간격, 재기동해도 카운터가 보존되고 감사로그에 기록된다. 푸시·감사로그에 문의 본문을 포함하지 않는다. 운영 답변과 공지 변경은 내용 없는 운영 감사 기록을 남긴다.

## 공지

제목 100자/본문 5000자의 텍스트 공지이며 HTML을 실행하지 않는다. 초안/게시, 전체/웹/Android 대상, 시작·종료 시각, 첫 진입 모달 여부를 관리한다. 대상과 유효 기간은 서버에서 확인한다. 공지 목록 최대 100건, 첫 모달 최대 10건이다. 초안과 아직 시작하지 않은/종료된 공지는 공개하지 않는다. 게시 중지는 수정 화면에서 공개 게시를 해제한다.

웹은 첫 진입에서 한 번 확인하고 닫기 후 탭 세션의 새로고침/라우트 이동에서도 다시 띄우지 않는다. 네이티브는 동의 후 앱 루트 마운트 시 한 번 확인한다. 로그인 계정의 오늘 숨김은 서버에 저장해 기기 간 공유한다. 익명은 기기에만 저장한다. 모두 Asia/Seoul 다음 날 00:00에 오늘 숨김이 만료한다. 닫기는 실행 중에만 유효하며 영구 숨김과 다르다. 공개 목록에서는 숨긴 공지도 볼 수 있다.

웹·네이티브 공지 확인은 5초 상한이며 요청 중 사용자 조작/화면 이동/계정 변경 시 늦은 모달을 띄우지 않는다. 웹 처음 사용 안내는 공지 종료 뒤 표시하여 두 안내를 겹치지 않는다. 조회 실패가 앱 사용을 막지 않는다.

## 검증과 후속

권한·본인 조회·요청 ID·답변·계정 삭제·대상/기간·계정 공유·KST 만료·outbox 상한은 CommunityIntegrationTest가 검사한다. PostgreSQL CI에도 포함한다. 브라우저 검증은 전 API fixture이며 운영 DB에 가짜 문의·공지를 만들지 않는다. Android 번들 검증은 실기기 접수/모달/푸시 확인과 구분한다.

스토어 평가 링크는 앱 게시 이후 연결한다. 첨부파일, 문의 대화 스레드/사용자 답변 알림, 네이티브 운영 편집, 앱 버전별 업데이트 안내는 후속 범위다. 현재는 강제 업데이트가 아니다.

2026-10-09 한국 클라이언트→Render 공개 API에서 실제 검증했다. Issue#19, 무작위 시험 기기 하나·세션28 하나·직렬43요청. 기존 사용자 식별자를 쓰지 않았고 순위 요청/삭제/외부 수집을 수행하지 않았다. 시험 게임은 ENDED로 보관했다. 기기 소유 식별자는 로컬 private 파일에만 보관하며 게시하지 않는다.

## 계약 결과

PASS. 실제26기업 목록·분야·공식 출처/확인일·시세26개와 가상 픽 이유/위험/뉴스를 확인했다. 픽의1개 종목을2주 매수→같은 요청 ID 재전송(체결1건 유지)→1주 매도했다. 잔여1주의 가격/평가를24턴에 걸쳐 검증하고 현금+보유 평가와 총자산을 대조했다. 원장2건은 모든 턴에서 같았다.

진행 응답은 자산34개의 현재/직전 최대2점이다. 마지막 턴의 기본 전체 응답24점과 compact의 보유·현금·평가·원장·가격·픽을5회 대조했다. 선택 종목 상세24점은 마지막 가격과 일치했다. 미래 턴400·타기기404를 확인했고 종료 후에도 원장/상세가 유지됐다. 웹 브라우저 fixture 성공과 달리 이 결과는 실제 운영 HTTP/DB에 시험 게임을 저장한 검증이다.

현재 코드의 getCurrentTurn/preview는 활성 세션을 PESSIMISTIC_WRITE 경로로 조회한다. 턴 진행/거래 잠금은 정합성 때문에 필요하며 측정만 보고 제거하지 않는다. BE-28 후속에서 서버 측 처리/DB 왕복·잠금과 첫 요청 기동 시간을 관측한 뒤 최적화 여부를 결정한다. 전 시장 수입/검색 설계는 BE-22에서 이어가며26기업을 전 시장 완료로 표시하지 않는다.

## 재검증 방법

`node --test scripts/verify-game-live.test.cjs`는 네트워크를 mock으로 대체한다. 명시 플래그 없는 실행의 무접근, 서버 실패 시1회 중단, 격리된 전체43요청과 순위/삭제 없음이 로컬/CI 검사 대상이다. CI에서 실제 운영 검증을 실행하지 않는다.

운영 검증을 다시 하려면 다음 명령을 의도적으로 실행해야 한다. 새 실행마다 새 기기의 게임 하나를 저장한다. 같은 보고서 경로는 덮어쓰기 전에 거절한다. 실패는 반복하지 않고 부분 보고서/원장을 보존한다. JSON옆 `.private.json`은 기기 소유 권한을 포함하므로 커밋/게시하지 않는다.

```powershell
node scripts/verify-game-live.cjs --base-url https://firewatch-backend-q3cv.onrender.com --report <새로운-로컬-보고서-절대경로.json> --write-isolated-game
```

전체 관측은 [JSON 결과](result-20261009.json), 실행 범위는 [계획](plan.md)을 따른다. 앱 코드/웹 번들/백엔드 운영 코드를 변경하지 않았고 APK/EAS 요청0이다.

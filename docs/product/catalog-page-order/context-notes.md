# 설계 근거

부분 일치 GIN은 빈 전체 목록과 깊은 페이지의 정렬을 해결하지 못했다. 검색어가 없을 때의 이름/코드 순서에 맞는 작은 B-tree를 추가하고 CASE 우선순위를 입력이 있는 검색에서만 유지한다. 공백뿐인 입력은 빈 목록과 같다. 구두점만 입력한 경우도 기존 검색 경로를 따른다.

OFFSET 페이지 계약은 웹과 앱에서 사용하므로 이번 작업은 커서 전환을 포함하지 않는다. 데이터 규모가 커지면 깊은 OFFSET의 스캔 비용은 남을 수 있다. CI 단일 프로세스 결과를 운영 HTTP 개선율로 확대하지 않는다. 운영 데이터 삭제·EAS 빌드는 없다.

초기 cdc0082·PR CI37935855294에서 B-tree는 첫 페이지에만 선택됐다. 마지막 페이지 시세0행은 기존38.75/후보37.48ms, 전 상품 가상 시세는41.42/38.38ms로 큰 비용이 남았다. 그 결과를 개선 완료로 주장하지 않고 페이지의 이름/코드만 먼저 선택하는 경로로 보완했다. COUNT의 LIKE '%%'는 NOT NULL search_text에서 항상 참이므로 빈 페이지 선택에서는 그 조건을 제외한다. 기존 SQL 대조와 NBSP의 total/items 일치도 확인한다.

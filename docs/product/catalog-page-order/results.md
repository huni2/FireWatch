## 변경과 보존

기존 쿼리는 입력이 없을 때도 정확 일치 CASE 정렬과 전체 메타데이터·시세 연결을 페이지 제한 전에 수행했다. 최종 쿼리는 정규화 결과도 비어 있는 공백 입력에서 이름/코드로 페이지를 먼저 고르고 최대50행에만 메타데이터와 시세를 연결한다. 빈 목록의 LIKE '%%'는 NOT NULL search_text에서 항상 참이므로 페이지 선택에서 제외한다. COUNT는 기존 계약을 유지한다.

실제 이름·초성·코드·구두점·NBSP/유니코드 공백 검색은 기존 우선순위와 검색 의미를 유지한다. 기존 SQL과 첫/다음/마지막/범위 밖·동일 이름·필터 결과를 대조했고 저장된 시세/null·회사 행 보존을 확인했다. 테스트용 전 상품 시세는 고정1000의 가상 값이며 전용 테스트 트랜잭션에서 롤백된다. 운영 데이터 삭제나 시세 변경은 없다.

## 재현과 한계

최종 두 CI의 catalog-search-measurement artifact에 catalog-search-page-order.json을 보관했다. [push CI](https://github.com/huni2/FireWatch/actions/runs/37937510477), [PR CI](https://github.com/huni2/FireWatch/actions/runs/37937515767)에서 전체 계획과 수치를 확인한다.

첫 후보 cdc0082는 첫 페이지만 인덱스를 선택했고 마지막 페이지에서는 전체 정렬이 남았다. 그 결과를 완료로 처리하지 않고 페이지 키 선택/상세 조회 분리로 보완했다. 고정된 기존→최종 순서와 작은 표본의 CI 관측이므로 운영 HTTP 개선율로 확대하지 않는다. OFFSET의 좁은 키 스캔은 남으며 전체 해외 자료처럼 규모가 커지면 재측정한다. pg_trgm·추가 서버·APK/EAS 빌드는 도입하지 않는다.

Render에 최종 서버를 배포하면 CREATE INDEX IF NOT EXISTS로 이름/코드 B-tree가 추가된다. 환경변수는 필요 없다. 사용자 배포 확인 뒤 공개 전체2669상품·처음/다음/마지막/범위 밖·ETF/국가·초성 검색을 대조한다. 이 공개 확인은 모든 운영 DB 행 대조나 SQL 실행 계획 확인을 대신하지 않는다.

# BE-45 전체 목록의 깊은 페이지 정렬 최적화

BE-44에서2669상품의 마지막 페이지 서비스 중앙값65~69ms, 단일 목록 SQL 약64ms를 관측했다. 검색어가 없는 조회에도 정확 일치 우선 CASE가 포함돼 이름/코드 정렬 인덱스와 일치하지 않았다.

빈 입력의 전체/필터 목록은 이름·코드로 정렬하고 두 열의 B-tree 인덱스를 추가한다. 입력이 있는 이름/초성/코드 검색의 정확 일치 우선 순서는 유지한다. COUNT·최대50건·page 계약·시세 LEFT JOIN·미수집 null·기존 행은 유지한다. pg_trgm은 도입하지 않는다.

기존 SQL과 새 SQL의 동일 결과를 빈/공백/필터/동일 이름/처음/다음/마지막/범위 밖 페이지에서 대조한다. 전용 PostgreSQL에서 기존 CASE 정렬과 새 정렬의 시간·실행 계획·B-tree 크기를 동일 실행으로 비교한다. 시세가 없는 조건과 있는 조건을 구분하고 새 인덱스를 강제하지 않는다. 전체 CI·PR·머지·Render 반영 및 APK/EAS 보류를 기록한다.

  Neon(카드 불필요·만료 없음·유휴 시 컴퓨트만 정지)을 1순위로 권했으나 사용자가 이미 Supabase 프로젝트를 만들어와 그대로 채택 — 기술적으로 동등(표준 Postgres, 무료 티어 만료 없음). Render 자체 무료 Postgres는 30일 후 자동 만료(14일 유예 후 삭제)임을 WebSearch로 확인 후 기각. Turso는 JDBC/Hibernate 생태계 성숙도 우려로 후보에서 제외.
  Spring profile(`prod`, `SPRING_PROFILES_ACTIVE=prod`)로 분기해 로컬 개발은 H2 그대로 두고 프로덕션만 Postgres 전환 — `spring.sql.init.platform`으로 `schema-h2.sql`/`schema-postgresql.sql` 분리(H2의 `AUTO_INCREMENT`+`MERGE` vs Postgres의 `BIGSERIAL`+`ON CONFLICT` 문법 차이만 있고 나머지 동일). `./gradlew build` 재검증 통과(스키마 파일명 변경이 테스트의 인메모리 H2 설정에 영향 없음을 확인).
  Supabase 연결 정보 확인 과정에서 대시보드가 브라우저 확장 프로그램(번역 기능 추정)과 충돌해 React 렌더링 오류로 두 차례 깨짐 — 클릭 대신 URL 직접 이동으로 우회. **Direct connection은 IPv6 전용이라 Render(IPv4)에서 안 될 걸 화면 안내 문구로 확인**하고 Session pooler(IPv4 프록시, 포트 5432)로 연결.
  첫 재배포는 사용자가 Render 환경변수(`SPRING_DATASOURCE_URL/_USERNAME/_PASSWORD`)를 넣기 **전에** git push로 이미 트리거되어 있어서 `${SPRING_DATASOURCE_URL}` 플레이스홀더가 그대로 JDBC URL로 전달되는 걸로 실패(`Driver org.postgresql.Driver claims to not accept jdbcUrl`) — 환경변수 추가 후 수동 재배포로 해결. 재배포 성공 후 `/api/scheduler/trigger` 수동 호출 → Supabase Table Editor에서 `briefings` 테이블에 실제 행이 들어간 것까지 직접 확인(Render 컨테이너가 아니라 진짜 외부 DB에 쓰고 있음을 검증).

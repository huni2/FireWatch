# FireWatch — Log

이 프로젝트의 시간순 기억. 최신이 위로.

> **형식 계약 (훅이 파싱한다)**: 날짜 섹션은 `## YYYY-MM-DD`, 항목은 `- **[태그] 제목**: 내용`.
> SessionStart 훅이 최신 섹션의 **제목**들만 추출해 세션에 주입한다(태그 포함).
> 제목은 주입만 보고도 무슨 일이 있었는지 알 수 있게 쓴다.
>
> **담당 태그**: `[BE]` 백엔드(Kotlin/Spring) 코드 · `[WEB]` 웹(React/AntD) 코드 · `[APP]` 모바일(React Native) 코드 · `[PROJ]` 위키·문서·설정 등 코드 외 작업.
> 한 항목이 여러 영역을 건드렸다면 **항목을 쪼갠다** — 태그를 두 개 붙이지 않는다.

## 2026-08-19
- **[BE] module-1+module-2 구현 — 백엔드 스캐폴딩·감사로그 AOP·스케줄러/Gemini 연동**: `/pdca do firewatch --scope module-1,module-2` 승인 후 진행. Spring Initializr(start.spring.io)로 `backend/` 생성 시도 중 `bootVersion`을 명시하면 500 에러가 나는 걸 발견 — 3.x는 아예 목록에 없고 기본값(4.1.0)도 명시하면 실패, 파라미터를 안 주고 기본값에 맡기니 성공하는 걸로 확인(원인 불명, Initializr 서버 쪽 이슈로 추정). 결과적으로 Spring Boot 4.1.0 + Kotlin 2.3.21 + Java 21 toolchain으로 확정([[Decisions/0005-spring-boot-4]]) — Boot 4에서 `spring-boot-starter-aop`가 사라져(Maven Central에 3.5.3까지만 존재) `org.springframework:spring-aspects`로 대체, `spring-boot-starter-webflux`만으로 `WebClient.Builder` 빈이 안 잡혀 `GeminiClient`가 `WebClient.builder()`를 직접 호출하도록 변경 — 둘 다 `./gradlew compileKotlin`/`@SpringBootTest` 컨텍스트 로딩 실패로 실측 발견 후 수정.
  감사로그: `AuditedComponent`(event_type 선언용 인터페이스) + `HasClientIp`(WebFlux에서 ThreadLocal로 client_ip를 못 읽어 커맨드 객체로 흘려보내는 인터페이스) + `AuditContext`(FALLBACK을 예외 없이 알리는 ThreadLocal 헬퍼) + `AuditLogAspect`(`service` 패키지 전체를 포인트컷으로 SUCCESS/WARNING(임계값 초과)/FALLBACK/FAILURE 자동 판정). `AuditLogAspectTest`가 4가지 상태 전부를 테스트 전용 픽스처(`TestFixtureService`)로 재현·확인.
  스케줄러: `GeminiClient`(REST 형식은 WebSearch+WebFetch로 2026-08-19 현재 문서 확인 — endpoint `{base}/models/{model}:generateContent`, `x-goog-api-key` 헤더, `tools:[{google_search:{}}]`, 모델명은 `gemini-3.7-flash` 확인값이나 자주 바뀌어 env로 뺌) → `GeminiBriefingService`(GEMINI_API 이벤트) → `SchedulerJob`(SCHEDULER 이벤트, cron 08:00 KST, 오늘자 브리핑 존재 시 스킵) → `Briefing` 저장. 금/은/환율(BE-4)이 없어 `dataSourceStatus`는 항상 NORMAL. `recommendedStocks`/`interestKeywords` 등은 Jackson 3 패키지 이동(`tools.jackson`) 리스크를 피하려고 JSON 대신 쉼표 구분 문자열로 단순화(Design §3.1 주석에서 변경).
  검증: `./gradlew build`(컴파일+11개 테스트 전부 통과+bootJar) + `java -jar`로 실제 기동해 Netty 서버 뜨는 것까지 확인(더미 API 키). **실제 `GEMINI_API_KEY`로 라이브 호출은 아직 안 해봄** — 다음 세션 전에 사용자가 키를 발급해야 진짜 검증 가능. `Next-Tasks.md`(BE-1·BE-2 종료 기록으로 이동, BE-3 진행상황 갱신)·`Context.md`·`index.md` 갱신, ADR 0005 신설.

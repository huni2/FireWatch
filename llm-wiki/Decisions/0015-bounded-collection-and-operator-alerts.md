# 0015. 영속 수집 상태·제한 재시도·운영자 장애 푸시

날짜: 2026-10-07. 상태: 로컬 구현, 배포 전.

실제 뉴스와 시세를 축적하되 무료 Render의 외부 통신 비용/사용량과 반복 실패를 제한한다. 뉴스·금융지표·종목시세·브리핑별 수집 상태와 임대를 Supabase DB에 저장한다. 자동 반복 루프를 두지 않고 기존 폴링에서 다음 시각이 지난 작업만 시도한다.

실패/부분 누락은 30분 후, 두 번째 실패는 60분 후 재시도한다. 같은 종류의 수집은 한국 날짜별 실패가 총 3회에 도달하면 다음 한국 날짜까지 중지한다. 개별 종목이나 오전/마감 작업을 새로 만들어도 종류별 한도를 우회할 수 없다. 직접 전달된 HTTP 429는 즉시 해당 날짜 종류를 중지한다. 금융 배치 내부에서 삼킨 오류는 부분 누락 한도를 적용한다. 한 금융 배치는 여러 API 요청을 포함하므로 이 한도가 Render의 미공개 통신 제한을 보장하는 수치는 아니다.

성공한 관측값은 append-only 이력으로 보관하고, 실패·빈 RSS·빈 시세를 성공으로 기록하지 않는다. 종목 최신값은 더 오래된 시세로 덮어쓰지 않는다. 관심/보유/추천 종목을 수집하며 한 번의 수집 실행에서 종목 외부 호출은 최대 10건이다. 늦게 추가한 관심 종목은 독립 작업으로 처리한다. 브리핑과 포함 뉴스, 작업 완료 상태는 같은 DB 트랜잭션에 저장한다. 외부 호출은 트랜잭션 밖에서 한다. RSS 및 제공처 조회 기간 밖의 공백을 완전히 복구했다고 주장하지 않는다.

실패마다 FAILURE 감사로그와 종류/날짜별 장애 알림을 남긴다. 공개 알림에는 개인 종목·기기·토큰·외부 URL을 노출하지 않는다. 정상 데이터는 유지한다. 운영자는 설정 화면에서 기존 스케줄러 관리 키로 수신자를 지정한다. 기존 수신자 한 명을 교체하며 등록된 계정의 모바일/웹 푸시 구독만 사용한다. 관리 키는 화면 메모리에서만 사용하고 요청 후 지운다.

푸시 발송은 DB outbox 상태로 제한한다. 종류/날짜별 장애는 제공처 접수 성공 후 추가로 보내지 않으며 발송 실패는 최대 3회, 60분 간격으로 시도한다. 발송 실패도 FCM_PUSH/FAILURE로 기록한다. 외부 제공처 접수와 DB 완료 표시 사이에 프로세스가 죽는 경우 중복 푸시 가능성은 남으며 실제 기기 도착은 별도 검증이 필요하다. 성공 전에 해소된 장애는 발송하지 않는다. 브리핑 수신 시간/lastNotifiedDate와 운영자 장애 푸시를 분리한다.

Docker 런타임은 prod를 기본 사용해 외부 PostgreSQL 설정이 없을 때 임시 H2로 조용히 기동하지 않게 한다. 생산 DB 삭제, 초기화, 실제 푸시 발송 및 배포는 수행하지 않았다.

운영 후속: DB migration/배포, 운영자 수신자 등록, 네이티브 알림 허용·실기기 수신 확인. Google 계정 병합으로 설정 행이 교체된 경우 운영자 수신자를 다시 등록해야 한다.

Render 근거: https://render.com/docs/free — 비정상적으로 큰 외부 통신을 하는 무료 웹서비스는 중지될 수 있으며 숫자 임계치는 공개하지 않는다.

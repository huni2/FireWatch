# 0011 — Gemini Search Grounding을 빼고, 이미 가진 데이터를 요약·해설시키는 방식으로 전환한다

## 상태
채택

## 맥락

[[Next-Tasks]] BE-3와 [[Decisions/0010-rss-news-instead-of-gemini-grounding]]에서 이미 확정한 대로, Gemini 3 계열은 무료 티어에서 **Search Grounding 도구(`tools: [{"google_search": {}}]`) 자체의 일일 할당량이 0건**이라 항상 429/404였다(3.7/2.5/3.5 세 모델 실측 확인). 그래서 브리핑은 FALLBACK(금/은/환율만 제공)으로 운영 중이었고, 관련 뉴스는 별도로 RSS 피드로 대체했다.

사용자가 "어떻게든 Gemini API 키를 쓰고 싶다"고 요청 — 발급받은 키가 완전히 무용지물인 게 아쉬운 상황. 조사해보니 **막힌 건 Search Grounding "도구"의 할당량이지, Gemini API(`generateContent`) 자체의 무료 할당량이 아니다.** 이 프로젝트는 이미 다른 소스로 실제 데이터를 확보하고 있어(Yahoo/수출입은행 시세, RSS 뉴스) 애초에 Gemini가 실시간 검색을 할 필요가 없었다.

사용자는 추가로 "주식이랑 환율 보고 제미나이가 종목 추천하는 것도 하고 싶다"고 명확히 함 — grounding 없이도 시세 데이터를 근거로 한 테마주 추천은 유지해야 함.

## 결정

**Search Grounding 도구를 제거**하고, Gemini를 "실시간 검색"이 아니라 **"이미 수집한 데이터를 자연어로 요약·해설"**하는 역할로 바꾼다.

- `GeminiClient.fetchMarketBriefing()`이 고정 프롬프트 대신 **오늘의 금/은/환율 수치 + RSS로 받은 뉴스 제목·설명**을 파라미터로 받아 프롬프트에 그대로 삽입한다.
- 요청 안에 "실시간 시세 조회 없이 일반적인 상관관계 수준의 참고용 추천"이라는 점을 명시해 Gemini가 마치 실시간 검색을 한 것처럼 답하지 않도록 유도한다.
- `SchedulerJob.executePipeline()`의 실행 순서를 재배치: 금융 데이터 → **뉴스(RSS) → Gemini 호출**(뉴스를 프롬프트 재료로 써야 하니 Gemini보다 먼저) → 브리핑 저장 → 뉴스 DB 저장 → 푸시. RSS는 한 번만 가져와 메모리에 들고 있다가 Gemini 프롬프트와 DB 저장 양쪽에 재사용한다(중복 호출 없음).
- `tools` 필드를 완전히 제거했으므로 요청 자체가 일반 `generateContent` 호출이 됐다 — grounding과는 별개의 할당량을 쓴다.

## 근거

- **왜 grounding을 포기하는가** — 어차피 이 프로젝트는 이미 실제 금융 API(Yahoo/수출입은행)와 실제 뉴스 피드(RSS)로 "진짜 데이터"를 확보해뒀다. Gemini가 굳이 자기가 다시 웹을 검색할 필요가 없다 — 오히려 "이미 검증된 데이터를 자연스러운 문장으로 풀어쓰기"가 이 프로젝트 목적(아침에 3분 안에 읽을 브리핑)에 더 적합하다.
- **테마주 추천이 여전히 가능한 이유** — 종목 추천은 실시간 검색이 아니라 모델의 일반적인 금융 지식(예: "금값이 오르면 어떤 섹터가 유리한지")과 오늘 주어진 수치·뉴스 맥락을 조합한 추론으로 나온다. 실시간 정확도는 떨어지지만("오늘 정확히 이 종목이 몇 % 올랐다"는 식의 사실 확인은 못 함), "참고용 테마 아이디어" 수준으로는 grounding 없이도 충분하다고 판단 — 프롬프트에 이 한계를 명시해 사용자가 오해하지 않도록 함.
- **실행 순서를 바꾼 이유** — 뉴스를 프롬프트에 넣으려면 Gemini를 부르기 전에 뉴스가 이미 있어야 한다. RSS 호출이 실패해도(`runCatching` + 빈 목록) Gemini 호출 자체는 계속 진행되도록 해, 뉴스 API 장애가 AI 브리핑까지 막지 않게 했다.

## 결과·트레이드오프

**얻는 것** — 발급받은 Gemini API 키가 실제로 쓰이고, FALLBACK 모드 대신 다시 AI가 작성한 자연어 브리핑을 받을 수 있다. 무료 티어 할당량 문제(0건)에서 벗어남 — 단, 일반 `generateContent`도 자체 요청수 제한은 있으므로 완전히 무제한은 아니다(배포 후 관찰 필요).

**감수하는 것**
- 더 이상 "오늘자 실시간 뉴스"를 Gemini가 스스로 찾지 않는다 — RSS로 받은 뉴스 범위 안에서만 브리핑 소재로 쓴다.
- 종목 추천이 실시간 시세 확인 없는 일반적 추론 수준이라, grounding을 썼을 때보다 시의성이 떨어질 수 있다.

## 재검토 트리거

- 배포 후 실측해서 일반 `generateContent` 호출도 예상보다 자주 429가 나면 → 모델을 더 가벼운 것으로 바꾸거나 호출 빈도(하루 1회라 여유는 있음)를 재검토.
- Gemini Search Grounding 무료 할당량이 나중에 다시 열리면 → grounding을 다시 붙여 "실시간 검색 + 이미 가진 데이터" 조합도 고려 가능(상호 배타적이지 않음, [[Decisions/0010-rss-news-instead-of-gemini-grounding]]과 동일 맥락).

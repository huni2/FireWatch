# 0010 — Gemini Search Grounding 대신 RSS 피드로 실제 기사 링크를 제공한다

## 상태
채택 (네이버 검색 오픈API → 카드 등록 필요한 대안들 → RSS로 최종 결정, 아래 「검토 경위」 참고)

## 맥락

[[Next-Tasks]] BE-3에서 이미 확정한 대로, Gemini 3 계열은 무료 티어에서 Google Search Grounding 도구 자체의 일일 할당량이 0이라(3.7/2.5/3.5 세 모델 실측으로 확정) 브리핑에 "실제 뉴스 출처"를 넣을 방법이 없었다. 사용자가 "클릭하면 실제로 볼 수 있는" 관련 뉴스를 요청했고, 결제 전환은 이미 옵션에서 완전히 배제하기로 확정한 상태([[Next-Tasks]] BE-3, 2026-08-21).

## 검토 경위

1. **네이버 검색 오픈API(뉴스 검색)** — 처음 채택 시도. 그러나 실제로 애플리케이션을 등록하려 하니(developers.naver.com) "사용 API" 드롭다운에 "검색" 항목 자체가 없었다(사용자가 직접 화면 확인, "사용 api에 검색이 없는데"). 조사 결과 네이버가 검색 오픈API를 별도 플랫폼인 "NAVER API HUB"(네이버클라우드플랫폼, NCP)로 이전 중이며, 기존 Developers Center에서는 2026-07-30 무렵부터 신규 신청이 막힌 상태로 확인됨.
2. **NCP(네이버클라우드플랫폼) 가입** — 새 플랫폼에서 신청하는 대안을 제시했으나, 카드 등록 요구 여부가 불확실해 사용자가 명시적으로 거절("그냥 다른 무료 뉴스 API로 바꿀가요").
3. **Google Custom Search API** — 대안으로 검토했으나 이 역시 Google Cloud 프로젝트/카드 등록 관례상 불확실성이 있어 사용자가 명시적으로 비교 후 거절.
4. **RSS 피드** — 사용자가 최종 선택("RSS 피드로 대체 (API 사용자설/카드 전혀 불필요)"). 회원가입·API 키·카드 등록이 전혀 필요 없다는 점이 결정적 이유.

## 결정

**RSS 피드(아시아경제 증권, `https://view.asiae.co.kr/rss/stock.htm`)**로 실제 기사 목록(제목+원문 링크+미리보기+발행일)을 매일 브리핑에 함께 저장한다. RSS는 키워드 검색을 지원하지 않으므로(피드 자체가 "국내 증시" 카테고리로 고정) 사용자 관심 키워드 기반 검색은 하지 않고, 피드의 최신 항목을 그대로 가져온다(상위 5건).

- `briefing_news` 테이블 신설(BIGSERIAL/BIGINT AUTO_INCREMENT PK + `briefing_id` 평문 FK — 이 프로젝트 기존 관례대로 JPA `@ManyToOne` 관계 매핑 없이 평면 엔티티로 둠).
- `NewsRssClient`(client 패키지, JDK 내장 `DocumentBuilderFactory`로 XML 파싱, XXE 방지 처리) → `NewsService`(NEWS_API 감사 이벤트) → `SchedulerJob`이 브리핑 저장 직후 호출, 실패해도 브리핑 자체는 이미 저장됐으니 스케줄러 실패로 안 침(금융 API·FCM과 동일한 논-패탈 패턴).
- 웹은 `RelatedNewsCard`로 새 카드 추가, 각 항목은 `target="_blank"`로 원문 링크 클릭 가능.
- RSS URL은 `firewatch.news.rss-url`(환경변수 `NEWS_RSS_URL`)로 설정 가능하나 기본값이 이미 동작하므로 Render에 별도 환경변수를 추가하지 않았다.

## 근거

- **RSS를 최종적으로 고른 이유** — 유일하게 회원가입·API 키 발급·카드 등록이 전혀 필요 없는 방식. 네이버·Google 계열은 모두 가입 절차에서 막히거나(플랫폼 이전) 카드 등록 여부가 불확실해 사용자가 리스크를 감수하고 싶어하지 않았다. RSS는 공개 피드를 그냥 HTTP GET으로 가져오는 것뿐이라 이 문제 자체가 없다.
- **키워드 검색을 포기한 트레이드오프** — 원래 네이버 안에서는 사용자 관심 키워드로 검색해 맞춤 뉴스를 보여주려 했으나, RSS는 검색 API가 아니라 피드 구독이라 이게 불가능하다. 대신 피드 자체가 이미 "증권" 카테고리로 고정돼 있어 이 앱의 "아침 국내 증시 브리핑" 용도에는 크게 어긋나지 않는다고 판단.
- **JSON 컬럼 대신 별도 테이블** — `recommended_stocks`/`interest_keywords`는 쉼표 구분 문자열로 단순화했지만(Jackson 3 패키지 이동 리스크 회피, [[Decisions/0001-tech-stack-baseline]] 계열 판단), 뉴스는 항목마다 제목+링크+설명+발행일 4개 필드가 필요해 구분자 문자열로 욱여넣으면 파싱이 더 복잡해진다. 대신 `briefing_news`를 별도 테이블로 둬서(audit_logs·briefings·user_settings와 같은 패턴) 각 필드를 그대로 컬럼에 담았다 — JPA 관계 매핑(`@OneToMany`)은 여전히 안 쓰고 평문 FK만 써서 이 프로젝트의 "관계 매핑 회피" 기조는 유지.
- **Gemini 재검토 트리거는 그대로 둠** — 이 결정은 Gemini를 완전히 대체하는 게 아니라, 막혀있는 동안의 대안이다. Gemini 그라운딩이 나중에 풀리면 "AI 요약 텍스트 + 실제 뉴스 링크"를 함께 쓰는 것도 고려할 수 있다(상호 배타적이지 않음).

## 결과·트레이드오프

**얻는 것** — Gemini 상태와 무관하게, 그리고 어떤 외부 가입/카드 등록 절차도 없이 즉시 동작하는 실제 클릭 가능한 뉴스 링크.

**감수하는 것**
- AI가 정리해주는 자연스러운 요약문이 아니라 RSS 피드 항목 그대로(제목+스니펫)라 Gemini만큼 매끄럽진 않음.
- 사용자 관심 키워드 기반 맞춤 검색이 안 되고, 피드가 고정한 카테고리(증권)의 최신 뉴스만 가져온다.
- 특정 언론사(아시아경제) RSS 하나에만 의존 — 해당 피드가 개편되거나 중단되면 대체 피드를 찾아야 한다(다만 RSS는 대체 후보가 매우 많아 전환 비용이 낮음).

## 재검토 트리거

- 아시아경제 RSS 피드가 개편되거나 중단되면 → 다른 무료 RSS 피드(다른 언론사 증권 섹션)로 URL만 교체.
- Gemini Search Grounding 무료 할당량이 다시 열리면 → AI 요약과 실제 뉴스 링크를 함께 쓰는 조합 검토.
- 네이버가 NAVER API HUB에서 카드 등록 없는 개인 개발자 신청을 다시 허용하면 → 키워드 기반 검색이 필요해질 경우 재검토.

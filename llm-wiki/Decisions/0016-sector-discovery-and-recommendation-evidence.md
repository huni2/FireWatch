# 0016. 분야·기업 탐색과 근거 있는 개별 종목 추천

2026-10-07 추가 UX 결정: 사용자는 코드보다 회사명·주식 가격·그래프·관련 뉴스를 원한다. 기본 검색/관심 목록/차트 탭/분야 기업 상세의 티커 노출과 종목 화면의 직접 코드 입력 탭을 제거했다. 내부 API 식별자와 DB 관심 종목 값은 기존 티커를 유지하므로 데이터 변경이나 삭제가 없다. 기존 국내 이름표와 탐색 목록 이름을 사용하고 새 검색 회사명은 웹/앱 로컬 캐시에 보존한다. 조회 meta 회사명도 알려진 이름이 없을 때 활용한다. 단순 캔들 끝값을 실시간 현재가로 표현하지 않고 제공처 최근 시세 또는 마지막 기록 가격과 기준 시각을 표시한다. 관련 뉴스는 기존 보관함에서 회사명으로 조회하며 실제 저장 기사만 보여준다.

날짜: 2026-10-07. 상태: 로컬 구현, 미배포.

사용자 요구는 분야별 기업과 개별 종목 추천을 UX 중심으로 연결하는 것이다. 최신 추가 지적은 근거 없는 과거 추천을 의미 있는 추천 데이터와 구분해야 한다는 것이다.

웹·모바일 투자 후보에 분야 → 기업 소개 → 개별 선정 이유/위험/기사 → 보유 비교 → 차트·관심 등록·보관 뉴스 검색을 연결한다. 라이트/오렌지 기본은 유지한다. 분야/기업 목록은 외부 요청 없이 즉시 탐색하며 브리핑 조회가 실패해도 탐색을 사용할 수 있다. 기업 상세의 차트 조회는 관심 종목을 자동 등록하지 않고, 관심 등록은 명시적인 버튼에서 한다. 포트폴리오는 보유 여부와 같은 분야 기업 보유 수를 설명하며 투자 점수·수익률·개인 최적 추천을 만들어내지 않는다.

공식 기업 소개를 확인한 7개 탐색 분야·14개 한국/미국 기업으로 시작한다. 분류는 FireWatch의 탐색용 묶음이며 거래소 공식 산업 분류나 전체 상장기업 목록이 아니다. 회사명/영문 별칭/티커/분야 로컬 검색과 국가 필터를 제공하고 목록 외 회사는 기존 종목 검색으로 연결한다. 기업은 여러 사업을 할 수 있다. 출처와 정보 확인일은 기업 상세/목록에 표시하며 최신 재무정보·시세는 이 카탈로그에 넣지 않는다. 정본은 shared/discovery.ts다. BE-22의 PostgreSQL 카탈로그·ETF 검색 확장은 별도 미완료다.

Gemini는 개별 종목 이름·선정 이유·확인할 위험·제공된 뉴스 원문 URL을 구조화해 반환한다. 다른 종목 근거·제공되지 않은 URL을 제외하고 날짜별 briefings.recommendation_details에 저장한다. 옛 형식/깨진 JSON에 임의 이유를 보충하지 않는다. 후보/브리핑 태그는 추천 목록에 포함되고 이유·위험이 있으며 같은 브리핑에 제공된 http(s) 기사와 연결된 항목만 노출한다. 이 기준은 구조적 자료 충족 여부이며 AI 해석의 사실 검증이나 미래 수익 보장이 아니다. 기사와 실제 공시는 사용자가 확인할 수 있도록 연결한다. 제공된 자료가 부족하면 추천은 비어 있으며 분야 탐색을 대신 사용할 수 있다.

근거 없는 과거 기록은 현재 추천에서 제외하되 종목·날짜·당시 가격 등 선정 이력은 삭제하지 않는다. 삭제하면 과거에 실제 제시한 종목과 이후 가격 변화의 검증 경로가 사라진다. 가격 변화 카드도 'AI 추천 성과' 대신 '선정 이력 · 가격 변화'로 표시하고 근거 없는 기록 포함을 밝힌다. 이유 없는 기록을 근거 있는 추천 평가 데이터로 취급하지 않는다. 식별 불가/오염/중복 데이터 정리는 별도 증거와 삭제 범위를 확인할 일이므로 이 작업에서 수행하지 않는다.

검증: 백엔드 전체 회귀 및 Gemini 구조화·URL 제한·옛 형식, H2 저장/조회/과거 원본 보존. 웹 360/1280px 분야/국가/별칭 필터·기업 상세·근거 누락 제외·차트 읽기·관심 등록·뉴스 검색어 전달. 모바일 타입·린트/번들 확인. 실제 Gemini 신규 수집과 PG migration/운영 배포 및 네이티브 화면 검증은 별도다. 브라우저 미리보기 추천/기사는 테스트 자료다.

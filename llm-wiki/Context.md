## 2026-10-07 웹 계정 연결 작업 (실제 로그인 성공)
웹 /account에 Google GIS 공식 버튼과 기존 Google 토큰 검증 API, 기기별 서버 세션 저장/새로고침/만료·401 처리, 로그아웃/연결 기기 관리, 서버 운영 권한 확인에 따른 메뉴·감사로그 접근을 구현했다. Google ID 토큰은 저장하지 않고 서버 Bearer 세션만 기기 ID·만료와 localStorage에 보관한다. 계정 전환과 다른 탭의 세션 변경은 개인 화면을 새로 불러온다. 계정 삭제 기능은 추가하지 않았다.

## 2026-10-07 UI/UX 재리뷰 적용 (최신 화면 구조)
주요 메뉴는 내 기록/기업 탐색/시장 소식/게임이고 우측 계정·설정은 기록 안내/설정/도움말이다. 기업 탐색과 시장 소식은 내부 탭으로 세부 경로를 제공한다. 일반 설정에 운영자 푸시 입력을 표시하지 않는다. 웹 Google 로그인은 WEB-19 후속으로 아직 없으며 별도 운영 키의 메모리 인증 정책은 유지한다.
기업 검색·추천/분야 전환을 상단에 배치하고 가격/차트/뉴스/추천 근거/명시적 관심 등록을 회사 상세에 통합했다. 단순 조회는 관심 종목을 저장하지 않는다. 넓은 화면은 상세 패널, 좁은 화면은 Drawer이며 선택 상태가 크기 변경에도 이어진다. 지표는 마지막 유효 값의 날짜/과거 상태/미수집을 구분한다. 뉴스는 넓은 화면의 필터/기사 분할과 좁은 화면의 순차 배치다. 도움말 검색을 바로 올리고 메인은 저장 요약과 접는 입력을 제공한다.
게임 시작은 접는 고급 옵션 위에 있고 진행 소개는 줄였다. 모바일 시장·픽/주문/보유·체결 탭과 보유/체결 카드, 하단 다음 턴 행동, 총자산 변화 우선 복기를 제공한다. 회사·게임 데이터와 서버/DB 변경은 없으며 기존 기록을 삭제하지 않는다. 구현·검증 범위는 docs/reviews/2026-10-07-uiux-followup-review.md와 오늘 로그를 따른다.

API assetHistories는 시드로 첫 턴~현재 턴 가격만 제공하며 미래 자료는 보내지 않는다. 상세에서 턴 그래프/체결 표시/자산별 원장을 확인하고 매수·매도 주문으로 이동한다. 기존 가격/게임 규칙과 현실 데이터 분리는 유지한다. ADR 0017 참조.
회사명 중심 조회(웹·백엔드 배포 완료, 앱 실기기 미확인): 사용자 요청으로 종목 코드 입력/노출을 기본 종목·탐색·관심 목록에서 제거했다. 코드는 내부 조회/저장 식별자로 유지하고 회사명은 기존 별칭/검색 결과 로컬 캐시/시세 meta로 표시한다. 종목 차트에 최근 제공 가격·통화·한국 시간 기준 시각과 회사명별 저장 뉴스 5건을 연결했다. 가격 조회가 실패하면 0원을 표시하지 않으며 meta가 없으면 마지막 기록 가격임을 밝힌다. 운영 카카오 시세에서 meta의 이름·KRW·가격·제공 시각을 확인했다.
분야/기업 탐색(웹·백엔드 배포 완료, 앱 실기기 미확인): 투자 후보 화면을 7개 분야·14개 한국/미국 기업 시작 목록으로 개편하고 분야/국가/기업명·별칭 필터, 기업 상세, 보유 비교, 차트/관심 등록/보관 뉴스 검색을 연결했다. 공식 소개 출처/확인일을 표시하며 전체 기업 DB·추천 순위로 표현하지 않는다. 개별 AI 후보는 종목별 이유·위험·제공된 근거 기사 구조화 결과를 날짜별 DB에 저장하고, 세 조건이 없는 과거 추천은 기본 후보/브리핑 태그에서 제외한다. 이전 종목/날짜/가격 이력은 삭제·추정 보충하지 않으며 가격 변화 카드는 선정 이력으로 표시한다. 새 추천은 신규 수집 이후에만 생길 수 있고 제공 자료 부족 시 비어 있다. ADR 0016 참조.

수집 우선 보강(웹·백엔드 배포 완료, 앱 실기기 미확인): 뉴스/지표/종목/브리핑의 DB 작업 상태·종류별 임대로 중복 호출을 막고 실패는 30분/60분 후 재시도한다. 종류별 한국 날짜 하루 실패 총 3회 후 다음 날짜까지 중지하며 직접 HTTP 429는 즉시 중지한다. 실패는 FAILURE 감사로그와 종류/날짜별 장애 알림에 저장한다. 운영자 푸시는 설정 화면에서 관리 키와 기존 구독으로 수신자 한 명을 지정하며, 제공처 접수 성공 후 추가 발송하지 않고 실패는 60분 간격 최대 3회이다. 실제 운영자 등록·발송은 하지 않았다. 웹/앱 장애 배너와 수신자 등록 UI가 추가되었고 관리 키를 저장하지 않는다. 원본 뉴스는 링크별 누적하고 관심/보유/추천 종목도 수집한다. 시세 관측 이력을 append-only로 저장하며 한 실행에 종목 외부 조회는 10건까지다. 금융 제공처 일부 실패가 다른 정상 값 수집을 막지 않는다. 브리핑/포함 뉴스/완료 상태는 같은 트랜잭션에 저장하며 Docker 기본 프로필은 외부 PostgreSQL을 요구하는 prod다. 자세한 정책과 실기기/배포 후속은 ADR 0015 참조.

운영 데이터 소실 신고 확인: 읽기 전용 이력 조회에서 브리핑 44건/뉴스 항목 755건과 최신 10-06 지수/후보가 남아 있었다. 기존 latest가 오늘 날짜만 찾아 자정~새 브리핑 생성 전 404가 되고 배포된 뉴스/지수/후보 화면이 함께 비었다. 로컬 latest는 오늘 이하 마지막 저장 자료를 반환하도록 수정하고 미래 자료를 제외했다. 기준 날짜를 표시하며 당일 푸시 판정은 변경하지 않았다. 없는 API의 500 오분류도 404로 정정했다. 웹·백엔드 배포 후 브리핑 45건·연결 뉴스 775건 보존과 뉴스 조회 복구를 확인했다.

최신 테마 요구: 기본은 라이트 모드. 웹은 저장된 선택이 없거나 저장소에 접근할 수 없으면 라이트로 시작하며 사용자가 선택한 다크 모드는 유지한다. 모바일 주요 화면 전체와 상단/상태 바, Expo 기본 interface도 라이트로 통일했다. 오렌지 포인트와 웹의 다크 선택 기능은 유지한다.

턴 결과는 자산별 직전 보유 수량 × 가격 변화로 설명하며 이번 턴 매도와 공매도도 포함한다. 시드 기반 가상 사이드카는 지수 주문만, 가상 종목 거래정지는 해당 종목 주문만 한 턴 제한한다. 거래정지는 직전 가격으로 평가하며 다음 턴 진행을 허용한다. 사건·차단 이유·해제 조건을 웹/모바일에 표시한다. 게임은 POST 응답으로 완결하고 SSE는 도입하지 않았다.

최종 게임 요구: 실제 자료를 사용하지 않는 완전 가상 시뮬레이션. 시드 기반 24턴, 가상 회사 5개, 시장 사건 6개, 무작위 가상 날짜와 뉴스·지표·시나리오 픽을 생성한다. 새 게임의 거래/턴/상태 조회는 외부 제공처를 호출하지 않는다. 클라이언트 즉시 금액 계산 + 서버 체결 검증, 거래 원장 반복 조회 축소. 기존 실제 자료 세션은 별도 기록으로 보관하고 새 가상 게임 시작 버튼으로 전환한다. 실제 뉴스/AI 추천 기록은 게임과 별개로 유지한다.

뉴스 보관함: /api/news의 from/to/q/page/size로 독립 RSS 저장소와 과거 briefing_news를 함께 조회한다. 링크 중복 제거·한국 시간 날짜 범위·제목/설명 문자열 검색·페이지 이동. 조회나 수집이 이전 기록을 초기화/삭제하지 않는다. 수집 전 기사/원문 전체는 보관하지 않으며 종목별 수집 커버리지는 기존 시장 RSS에 제한된다. 운영 DB 초기화 여부는 직접 확인하지 않았고 배포 설정은 Supabase(prod)다.

시각 요구는 최초 짙은 바탕 + 오렌지에서 기본 라이트 + 오렌지로 정정됐다. 공유 색상/radius 토큰, 웹 메뉴·포트폴리오 첫 화면·게임, 모바일 독립 게임을 적용했다. 게임은 날짜순 투자 연습이 아니라 **무작위 날짜의 별도 가상투자게임**이다. 기존 시간순 설명은 ADR 0014로 정정한다. 같은 턴 가격을 DB에 저장하고 주문 미리보기/확인 단가/거래 총액·영수증/턴 변화액을 제공한다. 가격 누락은 평가 미확정(null)이며 다음 턴 보유 가격이 없으면 턴을 유지한다. AI 후보는 빈 이유를 표시한다. ThreeUI MIT 토글을 적용하고 라이선스를 포함했다. OriginKit 소스는 복사하지 않았다. 모바일 주요 화면은 라이트 토큰으로 개편했고 선택형 다크모드는 후속이다.

검색 인프라 결정: 사용자가 OpenSearch 도입을 보류했다. 운영비 0원과 Oracle 가입 불가를 고려해 Cloudflare Pages + Render + Supabase를 유지한다. 다음 검색 개선은 PostgreSQL 종목/ETF 카탈로그·별칭·검색 인덱스를 활용하는 방향이며 아직 구현하지 않았다. 별도 검색 서버 추가·유료 서비스 전환은 진행하지 않는다.

FireWatch는 개인 포트폴리오를 작성하고 점검하는 앱으로 확장했다. 웹/모바일 첫 화면은 목표·기간·성향·계좌·월 투자금과 보유 자산 입력이다. 원금 비중/집중/입력 지수 중복, 규칙 기반 구성 초안, 장후 수집 시세, 장전 시장 후보, 독립 뉴스 피드, 별도 단기 투자 메뉴와 가상투자 게임을 제공한다.

`shared/investing.ts`에 공통 계약/라벨을 둔다. backend의 PortfolioService·MarketCollectionService, 웹/모바일 portfolio·candidates·practice 기능과 additive SQL을 추가했다. 로컬 변경이며 운영 배포와 운영 DB 이전은 하지 않았다. 범위·제약·검증은 `docs/product/portfolio-mvp.md`, 결정은 [[Decisions/0013-portfolio-product-identity]].

공개 출시 전 계정 세션/관리자 감사로그 권한, 기존 소유자 ID 이전, PostgreSQL 사전 검증과 실기기 왕복이 필요하다. 개인별 종목 점수와 최신 비용 기반 ETF 비교는 후속이다. 공통 토큰과 모바일 주요 화면 라이트 개편은 완료했다. 모바일 선택형 다크모드와 실제 설치 검증은 별도 후속이다.

## 스택 / 구조 (명세서 근거)

- **Backend**: Kotlin(JVM 17/21) · Spring Boot 3.2+ · Spring WebFlux(WebClient, Gemini/금융 API 비동기 호출) · Spring AOP + Logback + JPA(감사로그 자동 수집·영속화) · Firebase Admin SDK(FCM 트리거) · DB는 SQLite/H2(로컬)→PostgreSQL(운영 후보).
- **Web**: React 18 + Vite · Ant Design v5(`ConfigProvider` + `darkAlgorithm`) · Recharts/Ant Design Charts(환율·금/은 시계열, 감사로그 응답시간) · Framer Motion(수치 틱 애니메이션, 카드 페이드인) — 근거 [[Decisions/0002-ui-framework-selection]].
- **Mobile**: React Native(Expo) · NativeWind(Tailwind 클래스) · Expo Notifications/FCM · React Native Reanimated(60fps 모션).
- **AI/외부 데이터**: Gemini 3 Flash Free API(Google Search Grounding, 일 1,500회 무료) · Yahoo Finance(yfinance) / 한국수출입은행 API.
- **인프라(전부 무료 등급, 카드 미등록)**: Web은 Cloudflare Pages(`https://firewatch-eqp.pages.dev`), Backend는 Render 무료 플랜(`https://firewatch-backend-q3cv.onrender.com`, 15분 무활동 슬립 → GitHub Actions가 매일 08:00 KST에 깨움), DB는 Supabase Postgres(Render는 영구 디스크가 없어 H2 파일 DB가 슬립 사이클마다 초기화되는 걸 실제로 겪은 뒤 전환 — [[Decisions/0009-persistent-db-supabase]]), Push는 FCM. Oracle Cloud는 가입 자체가 막혀 Render로 전환했다 — [[Decisions/0008-deployment-render-github-actions]].
- 상세 근거는 [[Decisions/0001-tech-stack-baseline]].
